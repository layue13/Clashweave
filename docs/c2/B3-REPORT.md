# B3:战斗姿态与移动的融合(第一批)

状态:**草稿,等待审核**。日期:2026-10-13。基线:`work`(含 B2),分支 `b2/locomotion`。

## 1 结论

- 持刀进入战斗态(服务端 `engaged`)后,待机姿态原先把全身包括腿冻在 `light_1` 第一帧,边走边滑。现在**躯干、手臂、刀继续保持待机姿态,腿改为跟随 B2 的移动动画**;静止时仍是待机的分腿站姿。
- 动作进行中(轻击、重击、居合等)腿仍由烘焙轨迹接管(轨迹自带步法),不变。
- 腿的"保留比例"按 `1 − min(1, 肢体摆动幅度×3)` 为目标做帧率无关的指数追随(每 tick 0.3),所以开始/停止走动、动作结束回到待机时腿平滑过渡,不会跳变。
- 顺带:裸手挥拳时被占用的手臂肘部保持约 25° 的放松弯曲,不再是直棍。

## 2 实现

| 部分 | 内容 |
|---|---|
| `PoseDriver` | 新增 `stance`:当前姿态是待机站姿而非动作。 |
| `BodyRig` | 新增 `legHold`/`legHoldTarget`,随 `chase` 追随。 |
| `CombatBiped` | 战斗叠加层中腿的混合权重用 `weight × legHold`;其余(躯干、头、手臂、枢轴)仍用 `weight`。待机站姿的骨盆偏移为 0,所以腿与躯干的枢轴不会错位。 |
| 夹具 | `--move-verify 800+角度`:用轻击拔刀,在服务端保持 engaged 的 60 tick 内走路再超过窗口继续走。 |

## 3 验证

- JUnit 全过。
- 实机侧面拍摄 `b3-stance-90-3`:待机站姿(刀前指、双手在胸口)走路时,躯干与手臂稳定,腿迈步,躯干与腿连着;超出 engaged 窗口后(未战斗但刀在手)是普通走路,手臂带刀自然摆动。
- 没有逐帧对比"改前"(B2 版本)的走路画面,"改前腿被冻住"是依据代码(`PoseDriver` 站姿轨迹在第 0 帧全身接管)得出的,不是拍到的。
- 未做:动作进行中带位移时的腿(仍是轨迹步法);进入/退出战斗态时全身权重的过渡(沿用 B1 的接管追随);战斗回归、性能 A/B;锁定目标时的朝向行走(侧步/后退)。

## 4 已知问题

1. 战斗态走路时躯干是固定站姿,不随步伐扭转;速度很快时上身显得僵。
2. 未战斗但刀在手时,手臂是移动层的自由摆动,刀随手腕晃动,没有"持刀行走"的专用姿势。
3. 夹具靠 60 tick 窗口,服务端参数改变会让窗口变化。
