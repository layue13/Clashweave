# C2b-2:躯干前倾与侧倾

状态:**草稿,等待审核**。日期:2026-10-13。基线:`c2b/segmented-limbs`(PR #21),分支 `c2b/torso-lean`。

## 1 结论

- 用户反馈"上半身太直"。原因:躯干只有绕竖直轴的扭转,没有俯仰与侧倾,轨迹里也没有这两条数据。
- 现在躯干作为一整块**绕腰部**(脖颈下 12 px)转动:前倾、扭转、侧倾用同一个旋转 `Rz(-side)·Ry(-yaw)·Rx(lean)`。躯干方块、两个肩点、头都经过这一个变换,不会出现"胸弯了、肩膀留在原地"。
- 轨迹升到 v3,每个动作有前倾曲线与跟随扭转的侧倾。真实画面(`c2b3-pose-90-1`、`-140-1`)可见:`heavy` 举刀后仰 → 下劈前倾 → 收势回正;轻击前探;`iai` 前冲。
- 构建 `BUILD SUCCESSFUL`,JUnit 219 项,0 失败。

## 2 实现

| 部分 | 内容 |
|---|---|
| 轨迹生成 `art/katana/motion2.py` | 关键帧增 `lean`(度,正为前倾)、`side`(度,正为向玩家右侧;默认 `-0.2×yaw`,随扭转略倾)。肩点改为 `torso()`:绕腰部先俯仰、再偏航、再侧倾,再加骨盆。输出 `version: 3`、`torsoLean`、`torsoSide`。 |
| 前倾曲线 | 中段站姿 3°;轻击 (−4, 3, 14, 18, 8)(蓄力/起始/有效末/过冲/残心);`light_3` 上撩 (8, 6, −2, −5, 2);`heavy` (−10, −6, 22, 28, 10);`iai` 0 → 8 → 6 → 16 → 20 → 8;`sheathe` −6(血振上扬)→ 12 → 4 → 6。 |
| 手与刀随胸 | 手和刀由手臂端着,应随胸口一起倾:对刀的朝向与手的中点施加"只含前倾与侧倾"的那部分旋转 `Ry(side)·Rz(yaw)·Rx(−lean)·Rz(−yaw)`(作者位置已含扭转,不重复施加),绕腰部(含骨盆)转动。 |
| 刀鞘上的左手 | 自由手搭在鞘口,刀鞘挂在骨盆上,所以随骨盆平移(此缺陷 v2 起就有,前倾把它放大了)。 |
| 读取 `TrackData` | 接受 v2(躯干直立)与 v3。 |
| 姿态解算 `LimbSolver` | `torsoPoint/torsoRotate/torsoAngles/shoulderPoint(Pose)/neckPoint`;手臂的弯曲坐标系随胸口旋转(奇点轴与侧向参考都乘上躯干旋转),腿挂在骨盆上不随胸转。 |
| 模型 `CombatBiped` | 躯干方块、头、头外层的枢轴取 `neckPoint`,躯干角度取 `torsoAngles`;手臂枢轴取随躯干的肩点。 |

## 3 验证

- 生成器自检全部通过(手够得到违规 0、有效帧刀刃在服务端扫掠内)。`iai` 的可见刀尖加步进由 2.91 增至 3.24,首次达到服务端判定距离 3.2。
- 单元测试新增:游戏端躯干变换与生成器 `torso()` 是同一个变换(误差 <1e-3 px);肩点恰在 ModelRenderer 画出的躯干方块的肩部锚点上;前倾使肩点前移。
- 手部每 0.5 tick 最大移动量与 v2 相当(`light_2` 0.222 对 0.196;修正前一版曾达 0.734,见 §4)。
- 全轨迹 IK:可达误差 2.99e-7;右臂 24/168 样本略够不到(最大 0.058,既有问题,见 C2b-1 §5);**左臂 0**;腿 38/36(小幅)。旋转连续性:右臂 0.82、左臂 0.62、右腿 0.19、左腿 0.58 rad,**无任何因数据跳变而豁免的步长**(C2b-1 里 `iai` free→grip 的跳变也随左手跟随骨盆而消失)。
- 未运行:战斗回归、性能 A/B(纯客户端外观改动,按当前口径放到里程碑)。

## 4 过程记录(含失败)

- 第一版生成器只让肩膀随躯干前倾,手停在直立躯干的作者位置,够得到修正逐样本大幅变化,手在相邻采样间跳动(`light_2` t=7.0 单步 0.734,v2 为 0.079)。改为手与刀随胸倾斜后恢复正常。
- 曾怀疑手臂奇点被躯干转动带到动作经过处,于是让手臂弯曲坐标系随胸口转动;这一项是正确的建模,但当时的大步长实为上面的数据跳变。

## 5 已知问题

1. 躯干仍是整块,只在腰部折;胸髋分段(胸比髋转得多、腹部弯曲)未做。盔甲胸甲随整块躯干摆动,不受影响。
2. 前倾数值是手调的经验值,未与参考视频对照。
3. 第一人称不受影响(C2a-2 未做)。
