# B2:玩家移动层(第一批)

状态:**草稿,等待审核**。日期:2026-10-13。基线:`work`(含 B1),分支 `b2/locomotion`。

## 1 结论

- 玩家在站立、走、跑、跳/落/落地时由 `Locomotion` 写入目标姿态,`BodyRig` 做帧率无关的指数追随;不再是原版的直棍摆动。
- 走路:躯干随步伐反向扭转并轻微起伏,摆动腿屈膝、支撑腿伸直,手臂反相摆动且前臂带弯;冲刺:前倾、肘折、抬膝。头部抵消躯干扭转。
- 跳跃:起跳手臂前伸、膝收起,落地下蹲后恢复(`b2-move-90-2` 十帧可见)。
- 参考 Mo' Bends(MIT)的手感与结构,公式在我们的骨架上重写,未复制其代码。
- 修复肘/膝弯曲时外侧的断口:关节处加一个转角为弯曲一半的 4 px 方块(见 §3)。穿对应盔甲的肢体仍为整块,不加。

## 2 范围

已做:站立、走、跑、潜行、跳、下落、落地、游泳、骑乘(船、马、矿车)、爬梯、创造模式飞行。睡觉、拉弓/进食/挥拳仍为原版姿态(经平滑)。躯干、颈、肩、头绕髋部一起转,腿钉在髋上。

## 3 验证

单元测试:JUnit 全过(`LocomotionTest` 含各状态有限值、骑乘坐姿、爬梯相位)。

实机拍摄(`tools/p0/dual.py --move-verify <角度>`;游泳、骑乘、爬梯、飞行、睡觉在客户端临时搭的场景里用模拟人拍,因为玩家自身位置归服务端):

| 视角 | 标签 | 覆盖 |
|---|---|---|
| 90°(侧) | `b2-move-90-11` | 全部状态 |
| 150° | `b2-move-150-4` | 走、跑、潜行、跳(肘部) |
| 0°(背) | `b2-move-0-1` | 走、跑、潜行、跳 |
| 45°(背斜) | `b2-move-45-1` | 全部状态 |
| 180°(正) | `b2-move-180-1` | 全部状态 |

各视角下躯干与腿、肩与臂没有错位;肘、膝连续,无缝、无鼓包;手掌、鞋底面显示各自皮肤。战斗姿态回归拍摄 `b2-pose-90-1`:刀在手中、躯干前倾、握柄正常;旧基线 `b1-pose-90-1` 场景不同(有僵尸),不是逐帧对比。

性能(40 个走动的模拟人,`--move-verify 900`,基线为 C2b-1 jar `c2b1-dev`,候选为本分支,ABABAB 各 3 轮,每轮 4000 帧):帧时间被约 300 fps 上限卡住,平均值 3.334/3.376、3.333/3.334、3.333/3.334 ms(基线/候选),p95 3.70/3.99、3.64/3.72、3.72/3.76 ms;候选一轮出现 30 ms 的单帧最大值,其余 ≤11 ms。结论:40 人场景下没有可测的平均帧时间回归,p95 最多高约 0.3 ms;上限卡住了分辨率,小于此的差异看不出来。

## 4 过程中发现并修复的缺陷

1. 肘/膝外侧断口:两段方块绕关节转动,外侧张开。先用转半角的方块填,方块角凸出约 0.8 px 显得关节鼓,改为八边形棱柱(凸出 ≤0.2 px)。
2. 前臂、小腿末端面贴图取错行,手端露出袖子的青色:UV 回移切口高度(Mo' Bends 同样做法)。
3. 前倾/扭转时躯干绕脖子转,下半截甩离腿:改为绕髋转。
4. 跑步手臂不摆、前臂定在胸前:改为摆幅约 60°、肘约直角、脚跟后踢。

## 5 已知问题

1. 睡觉、拉弓/进食/挥拳仍是原版姿态。
2. 潜行正面看头略低,下巴被胸口挡住一点(前倾 28° 的几何结果)。
3. 参数(幅度、前倾、起伏)是经验值,以观感迭代。
4. 自定义盔甲模型类不跟随姿态;64×64 皮肤未支持;第一人称不受影响。
5. 性能测量被帧率上限限制分辨率;未做战斗/网络回归(只动了客户端渲染)。
