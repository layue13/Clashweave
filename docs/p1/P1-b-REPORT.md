# P1-b 空中追击

状态:已合并进 `work`(PR 见提交记录)。术语:**通过**＝预设判据在记录的运行中成立;**失败**＝不成立,原运行保留;**未验证**＝没有运行。

## 1 做了什么

切上(`launcher`)命中后,目标浮空,新增两个动作,仍走同一套控制预算(`ControlBudget`):

| 动作 | 数据 | 作用 |
|---|---|---|
| `katana:air_light` | 启动 4、有效 2、恢复 9,伤害 3,射程 2.3,仰角 35°,`LAUNCH vy 0.45` | 追击轻击:再次抬升目标,可连接自己(`LIGHT`)或落斩(`HEAVY`)。命中取消窗口 [6,11) |
| `katana:air_slam` | 启动 5、有效 2、恢复 12,伤害 6,射程 2.3,仰角 45°,`SLAM vy 1.0` | 落斩收束:把空中目标按向地面,花掉剩余全部控制点并开始抗浮空保护 |

`launcher` 增加两条出边:`LIGHT → air_light`、`HEAVY → air_slam`,窗口 [7,15),要求前一击是真实的伤害命中(`hit`、`damageHit`)。所有数值是临时起点,可调,未验证为最终值。

规则(服务端):
- 新增效果类型 `SLAM`(`HitEffect`):目标须在空中(或刚落地不超过 `slamGraceTicks`=3 刻,避免网络延迟吃掉收束),`ControlBudget.exhaust`:点数清零并开始保护;预算已被连击用尽时落斩仍可把目标压下来,但不改变保护期。已在落斩途中的目标不能再被落斩。
- 抬升衰减:同一条链里每次被接受的抬升按 `chainDecay`(默认 0.75)递减(0.6 → 0.3375 → 0.2531),链在预算回满时重置。
- 落地冲击:落斩目标落地时服务端发 `SLAM` 语义事件,客户端画一圈烟与爆裂声。
- 轨迹:`art/katana/motion2.py` 增加 `air_light`(上挑)与 `air_slam`(落劈),重新生成 `katana.tracks.json`;视觉可及与服务端射程相差约 0.6 格(其他动作 0.4–0.55)。
- 配置(`CombatConfig`,"control" 类):`chainDecay`、`slamGraceTicks`、`slamRequiresAir`。
- 内容:`actions.json`、`style.json`、传统 `combat/katana.json` 同步。单元测试 `AirChaseTest`(预算、衰减、SLAM 模式校验、成品数据的连接),总数 255 全过。

## 2 实机验证

夹具:`dual.py --chase`(`ChaseReplay` 用真实输入逐步发 轻→轻→重(切上)→轻→轻→重;`NetworkScenario` 把静止的 200 血僵尸放回面前、给攻击者击退抗性、给僵尸击退抗性,以免普通命中把目标推出射程——这个抗性只作用于夹具,升力不是击退)。统计脚本 `tools/p0/p1b_stats.py`,结果 `docs/p1/p1b-shots/*-stats.json`。20 轮里第 0 轮是拔刀,有效 19 轮。

| 标签 | 延迟 | 追击×2 | 每轮被接受的抬升数 | 落斩接受 | 被拒绝的抬升 |
|---|---|---|---|---|---|
| `p1b3-chase-0` | 0 ms | 是 | 3(切上 + 2 次追击)×19 | 19/19 | 0 |
| `p1b3-chase-100b` | 100 ms | 是 | 3 ×19 | 19/19 | 0 |
| `p1b3-extra-0` | 0 ms | 想连打 5 次追击 | 3 ×19(上限不变) | 0/19(见下) | **57**(每轮 3 次多出来的追击抬升全被拒绝) |

- 抬升速度按衰减:首次 0.6,之后 0.3375、0.2531(`decayedVy`)。
- **无限浮空不可复现**:`extra-0` 里客户端每轮发了 5 次追击,服务端只接受 3 次抬升,多出的 3 次被预算拒绝(`accepted=false`),目标不再升高。
- `extra-0` 的落斩 0/19:那组实验客户端在第 5 次追击后才发落斩,此时目标已经落地或在保护期结束后的地面,按设计不接受;不是缺陷,但也**不能算落斩在"过量连打"下通过**。
- 画面(`p1b3-pose`,`--chase --pose-verify 90`):追击轻击从下向目标挑起;落斩命中后目标落地并有烟圈。图见 `p1b-shots/`。
- `--souls-view` 回归(`p1b-souls-0`、`p1b-souls-100`,在第一次实现之后的代码上):0 ms 61 次挥刀 63 次命中、100 ms 61 次挥刀 64 次命中,ACK 只有 START/MOVE_READY 与 100 ms 下的 2 次 `REJECT:STALE`(与之前报告的同类),`client_class_loads` 0,完成。之后只改了数值与宽限,没有重跑这组。

## 3 迭代与失败(保留)

1. 第一次 100 ms 运行(`p1b-chase-100`):19 轮落斩全部被拒——落斩到达时目标已落地(`airborne=false`,延迟让落斩晚了 2 刻)。处理:落斩启动 6→5,加 `slamGraceTicks`。
2. 把 `air_light` 抬升加到 0.55 想给更多空中时间(`p1b2-*`):0 ms 下目标飞得太高,第二次追击打不到(攻击者在地面、射程 2.3),整条链断在 2 次,没有落斩。撤回到 0.45。
3. 100 ms 的 `p1b3-chase-100`(第一次)"登录超时"、`p1b3-extra-100` 与重跑 `p1b3-extra-100b` 在第 4–5 轮突然结束,客户端与服务端同一刻停止,**原因没有查明**,没有可用数据;`p1b3-chase-100b`(重跑)正常。因此 100 ms 下"过量连打"这一项**未验证**。
4. 第一次实现的 `chaseTarget` 夹具把 `motionY` 当忙碌条件(地面实体的 `motionY` 恒为 −0.0784),目标永远不被放回;攻击者被僵尸击退出射程、被打死;第二玩家抢走命中——都是夹具问题,已逐个修正,运行记录保留。
