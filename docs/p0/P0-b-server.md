# P0-b 服务端适配（集成后继续补测）

生产适配独立于客户端包，目标计时归属按目标 UUID/持有者集合管理；退出最后归属、死亡、维度变化和下线恢复，仅在值仍为所写值时恢复。命中是一次普通原版调用，不修改瞬时字段、不取消递归调用。动作命中冻结后排序并延后提交；默认同时等待 3 个逻辑 tick 和 150ms 单调时间。

输入使用本次联网会话 token、严格递增序号、年龄上限、未来 stamp 与速率限制；网络线程只记录输入，游戏线程提交。同一锁完成到达登记和截止快照，截止后入队的输入不进入该次提交。此线性化接入留待本 PR 审核，不声称已经通过生产协议审核。窗口内的伪造回溯 tick 与真实按键不可仅凭协议字段区分；会话校验不是按键的密码学证明。

服务端每 tick 根据动作/防御/锁敌/受击/敌对目标计算交锋态，修订同步；默认友好保护与平时态方块右键放行。配置在 `config/clashweave/combat.cfg` 和 `katana.json`。实际轨迹是按各有效 tick 子采样的刀刃线段/AABB 窄相与原版方块射线，冻结朝向，不是半径内全命中。

## 限制与必带条件

这是阶段提交，联网双客户端运行、盔甲/药水/覆写实体/真正死亡重生换维度下线、1.2/1.5倍位移灵敏度、纵向/WASD/击退/持续低TPS、端到端反馈仍未验证；在 P0-c 集成阶段补测并给最终结论。

原版怪物/其它来源保持同步返回与原版结算语义，当前 Hurt 事件做已收到防御的即时减伤；不会把这些调用改成延后队列。因此外部来源还没有模组动作的回溯按键补偿。需要明示这一范围差异，不能拿 PvP 动作补偿冒充全部怪物攻击补偿。

累计预算单独允许原版走路/跳跃并保留动作总距离上限；END 看不到被原版接受后又返回原位的包内路径。墙由原版逐包处理。余量与原版移动 allowance 可能降低略超速检出率，须实测报告，不预先宣称作弊检测保证。
