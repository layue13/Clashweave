# P0-c 客户端、双人联调与占位资源

本阶段新增客户端输入、动作进度、握持渲染与生产状态包接入，同时修正双客户端发现的服务端接入缺陷。最终构建、指标、必带条件和未通过项统一见 [REPORT](REPORT.md)；P0-a/b 的报告保留各阶段实际输出，不用最终数字覆盖历史。

## 实现与接入

输入由真实 MouseEvent/KeyBinding 进入生产协议。持刀左键始终攻击，实体右键重击；平时态可交互方块保留原版右键，普通方块右键进入重击；交锋态屏蔽原版用途。Shift 的物理边缘跨持刀、状态变化与 GUI 持续跟踪，保持的 Shift 不产生新精准格挡。交锋态移动输入同时撤销 sneak 和 0.3 倍缩放；服务端也清除已收到的原版潜行标记。R 纳刀，中键锁敌；Alt/V/B 未实现意图返回明确拒绝，没有 F 键。

客户端预测本地已知交锋触发与合法空闲入口姿势，尚未确认的动作保持启动第 0 帧；收到服务端实例后推进，根位移等待 MOVE_READY。此前每次确认倒退 2–3 tick 的方案已弃用。此降级增加开始挥动前的往返等待，不宣称完整无等待预测。权威实例与进度用于两视角，切换 F5 不发攻击请求。派生等待服务端，不猜测命中成立。

状态包持有者版本包含会话凭据和配置，观察者使用独立副本并剥离凭据；不再入队后修改同一个消息对象。登录延后首包，配置重复发送至确认，避免 Forge 握手阶段包未到世界的问题。客户端时基使用最近服务端 tick 加本地单调经过时间，保留一个 tick 的边界不确定度，慢服采用实际观察周期。

动作输入在网络包中带原实例ID，服务器在缓冲前核对；旧实例已结束、被打断、空闲状态变成另一动作均明确拒绝，不把迟到派生解释为空闲攻击。实际100ms回放seq31/origin1返回ORIGIN_CHANGED，未启动新动作。包从28增至36字节，双方需更新。尚未实现意图在防御状态检查之前明确返回UNIMPLEMENTED。

第三人称玩家根使用冻结实例朝向，头部可观察相机；不修改实体旋转字段。第一人称手部保持视角局部挂点，34版尝试冻结相机变换后手柄移出屏幕，35撤回该变换；世界轨迹严格映射仍未验证，不能宣称第一人称世界朝向完全一致。盔甲头部渲染层及与其它玩家渲染器兼容尚未验证。

## 占位刀/鞘的位置与形态

按最新 `work` 180bc77 的原型说明 1.2 第 5 条及 S4b 审核后补记验收，未使用旧 S4b 截图作通过依据。本分支已用 merge 合入该版本，未 rebase。改动只涉及挂点、角度、尺寸及手部适配，没有因刀鞘更正重做动作/伤害/预算/防御/交锋模块；联网发现的问题另行修正。

资源用 [export_assets.py](../../tools/p0/export_assets.py) 可重复生成静态 OBJ 和 4×4 PNG 调色板；无需依赖 Blender 插件。1 OBJ 单位 = 1 方块，握点为原点，刀尖沿 +Y；Blender 常用坐标转换约定 `(x,y,z) → (x,z,-y)`，当前导出器直接写目标坐标，未声称实跑 Blender 导入。刀身宽/厚 0.12/0.07，鞘 0.13/0.12、长 1.25，刃端 1.17。ModelBiped 玩家根缩放 0.9375 被抵消一次，第一人称独立手部不重复抵消。

鞘固定左骨盆挂点，默认角度 45°（可配置 30–60°），偏移 x=0.32、y=0.55、z=0.18；潜行使用骨盆平移，不跟随上身倾斜或行走腿旋转。刀柄在右手局部坐标内，刀绕纵轴转 90° 显示刀面，挥动沿动作有效帧与恢复插值。第一人称使用独立 ModelBiped 手臂；手掌仍是原版方块，没有手指抓握骨骼。第一人称腰鞘为世界空间挂点，向下看可见，前视通常在视锥外。

## 联调中的失败与修正

初期夹具 OBJ 小数 UV 语法、Forge 自动连接调用顺序、客户端原版音频初始化并发以及过早并发登录均失败，相关运行不纳入验收。夹具改用合法 UV、完整连接辅助函数、等待原版声音初始化与串行登录；生产代码没有改写 SoundManager。正式启动器/非夹具音频启动仍未验证。

交锋测试发现单纯包装移动输入不足以撤销服务器已经收到的潜行状态；增加服务端交锋 END 清除。虚拟键夹具在 KeyInput 重置按键时曾制造 Shift 假边缘，修正为缓存并恢复脚本键状态后复跑；移动第二玩家导致锁敌超距离的夹具也作了隔离。上述失败不记作通过样本，最终脚本仍经过真实移动输入、原版 C08 和生产消息处理。

验证 mod 只在 `tools/p0` 独立源集与 jar，生产 `src/main` 没有探针/夹具代码。运行器使用新目录保留各轮日志，准备传送和动作开始握手的 S08 与超预算纠正分别统计。

final-29-zero 曾出现首客户端登录40s超时，未定位原版/联网启动原因，不算通过；新目录 final-30-zero 完整执行成功。正式启动器与启动可靠性仍需补测，不能把重跑成功写成首次启动没有失败。运动28–30的单次跳跃按键在握手后落地前松开，没有离地，排除为跳跃证据；31保持真实按键直至落地后起跳，日志补证峰值1.249187。修改仅在验证源集，不调用 setPosition 冒充跳跃。
