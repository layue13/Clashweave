# P0 审核与试玩修复

本次按审核后的 A1–A6 及原型说明第9节修复，追加在 prototype/p0-vertical / PR #12。以 d67c380 merge 最新 work 4b85c25，未 rebase。动作时序、防御、玩家目标的延后格挡、交锋同步分类公式未调整。此前报告的初次P0运行数据保留为历史，以下是修复后的验收。

## 原因与修复

真人反馈：“锁定距离有点短”“攻击的时候还会重置视角，有顿挫的感觉”。此前仅“ok”不是体验结果；这两条是实际反馈，不补造格数或主观次数。

锁敌原来读取 objectMouseOver.entityHit，受原版普通生存模式约3格实体拾取限制，服务端8格上限不等于客户端可选8格。现在客户端只发送LOCK意图；实体提示被忽略，服务器扫描实体，按眼部观察方向计算三维锥形角度，要求 canEntityBeSeen，排除自身/死亡/默认受保护友好实体。评分 = 距离/获取范围 + 角度/半角，越低越优，同分按实体ID升序，避免遍历顺序改变结果；浮点锥形边界容差1e-5度。配置 lockAcquireRange=16、lockKeepRange=20、lockConeHalfAngle=30；保持配置不足时提升到获取范围+1，形成迟滞。engageRadius仍为8，只用于敌对目标以你为目标的交锋判定及对应归属查询，不被扩大。再按LOCK仍解除。

攻击START原来发送同位置S08，包携带服务端过时yaw/pitch，100ms下会撤销客户端新观察。现在START只建立动作，客户端确认当前实例后，服务端用单调时钟建立累计位移预算，通过自定义StateMessage的MOVE_READY确认预算tick、服务端nanoTime和posX/Y/Z基准；nano仅作为服务端时间信息，客户端不与自己的nano直接相减。不传送，不写客户端坐标或旋转。累计算法/余量2tick/总距离上限/纵向及WASD和击退额度未调整；预算起点仍是收到合法实例ACK时，禁止过时实例启用位移。

真实S08保留原版位置处理、速度清零、地形初始化及C06回执。客户端连接时在解码后、packet_handler前包裹S08；NetworkManager仍将非优先包排队到主线程，实际执行时才采样当前yaw/pitch和prevRotationYaw/Pitch，以当前旋转交给原版handlePlayerPosLook，并在finally恢复四个旋转字段。玩家实体已存在时生效（包括切物品后的残余预算纠正），不改专用服包处理、不用旋转传送代替握手。第三人称承诺朝向规则和第一人称挂点未改。

## 1.7.10位置包源码核对

生成反编译源码：build/rfg/minecraft-src/java/net/minecraft/network/play/server/S08PacketPlayerPosLook.java。字段为三个double坐标、两个float绝对旋转、一个boolean；read/write没有相对坐标/旋转标志集合。func_148929_h()的boolean由NetHandlerPlayClient.java第642行写进C06的onGround，**不是相对旋转标志**。该类第631–652行的handlePlayerPosLook第641行直接setPositionAndRotation，第642行回执包也直接用S08旋转。NetworkManager.java第118–128及221行之后确认排队/主线程执行，包装不在Netty线程读取玩家旋转。开发环境反编译源码与实际Forge运行版本均为1.7.10，未套用新版本相对标志API。

## A4 输入朝向与校验

InputMessage增加按下yaw/pitch。服务端解码后只观察原版C03的位置/朝向历史，不替换包、不处理世界；主线程用输入到达前最近历史、500ms年龄、4格位置漂移、30度/tick最大转速与5度相位容差（均可配置）校验。失败回落服务端已知朝向并记录理由；缓冲请求保存其已校验快照，动作开始时取该序列对应结果。未来历史不能用于证明更早请求合法；相邻朝向包本身越过配置转速时也回落并记录HISTORY_TURN_RATE，不能仅靠同时伪造C03与输入快照通过校验。客户端没有自带动作定义。

100ms连续观察61次动作朝向全部通过校验，采用按下yaw后偏差全0；同一次START若采用旧方案的服务端已知yaw，偏差0.00647–0.22493度，均值0.13990度。这里是同一次采样的旧策略对照，不是另一次旧构建实验，慢速鼠标回放也不代表高速真人转向误差上限。JUnit证明180度伪造、NaN、越界pitch、过旧/位置漂移/缺失历史均回落，±180环绕、位置包保持朝向与未来样本排除正常。
