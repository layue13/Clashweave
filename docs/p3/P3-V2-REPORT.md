# P3-V2/V3 其余事件与怪物接入

## 1. 内容
- 事件绑定扩展(`bindings.json`):每条绑定可指定 `anchor`(actor/target)、`height`(实体高度的占比)、`dir`(`up` 或 `side`,后者取垂直于视线的水平方向,让斩痕总是横过屏幕)、`entity`(实体类简单名,有则优先于通用绑定)、`follow`(跟随效果:`followInterval`/`followDuration`,每隔若干刻在实体当前位置再放一次)。
- 新效果(`effects.json`):`break_generic`/`break_zombie`/`break_skeleton`(崩势,按怪物种类着色)、`stagger_stars`(崩势期间头顶旋转的小星,跟随 16 刻)、`slam_impact`(落斩:平躺的地面冲击环 + 尘土火花)、`launch_burst`(切上:地面环 + 上扬火花)、`afterimage_slash`(延迟斩/影缝:横向斩痕)、`mode_aura`(模式:脚下紫色环 + 上升光点)。
- 新发射器字段:`facing`(CAMERA/GROUND)、`dirSign`(±1,反向抛出)、`scatter`(起点随机范围)。
- `DefaultPresentation`:LAUNCH、SLAM、BREAK、DELAYED 优先走数据绑定,没有绑定时回退原有原版粒子;`ClientProxy` 每刻为 `mode > 0` 的实体放模式光环(含他人)。
- 怪物接入方式:不需要新网络(这些事件本就由服务端发给所有客户端);按实体类简单名加一行绑定即可。已为僵尸与骷髅各配一个崩势变体作示例,其余怪物用通用效果。

## 2. 验证
**渲染(固定点放效果,每刻一帧,0 ms,截图 `docs/p3/v2-shots/`)**:崩势在僵尸上为绿色、在客户端生成的骷髅上为骨白(实体过滤生效,日志 `VFX_EVENT kind=BREAK entity=EntitySkeleton effect=...break_skeleton`);落斩与切上为贴地平躺的环;延迟斩为横斩痕;模式光环在玩家脚下(而不是头顶,见 §3)。
**真实事件触发(`--posture/--chase/--sa/--mode`,日志 `VFX_EVENT`)**:BREAK(玩家与僵尸)、LAUNCH、SLAM、DELAYED、MODE 光环(自己与对方两端客户端)均在真实战斗事件上走到了数据绑定,无异常日志。这些运行不截图,**真实战斗中的画面观感未逐帧看过**。
单元测试:绑定解析(实体过滤优先于通用、未知效果/非法方向/缺跟随时长被报告并跳过)、`facing`/`dirSign` 校验。

## 3. 过程中的缺陷
- 客户端自己的玩家 `posY` 是眼睛高度,脚下的光环悬在头顶;改用 `boundingBox.minY`(跟随效果同)。
- 第一版崩势/切上/延迟斩偏小偏淡(浅色在亮天空/灰地上对比弱),加大尺寸并提高饱和度;星星从拉长火花改为带随机散布的小圆点。

## 4. 未验证 / 限制
- 100 ms 未跑(纯客户端表现)。
- 真实战斗里的实际观感未看帧;所有数值是起始值。
- 怪物只有僵尸、骷髅有专属变体;猪人、末影人、其他模组怪物走通用效果,且怪物的刀光/自带挂点(头、胸上报)没有做:目前用实体高度占比代替挂点,足够事件特效,持续型"绑在刀上"的效果只有玩家刀光。
- 模式光环每刻遍历所有已知状态的实体(小量迭代,非零分配);实体很多时可再优化。
- 星星跟随只在崩势事件的客户端实体存活期内;死亡时终止。
- 玩家崩势的特效在测试里出现很多次,印证 P2 已记录的"玩家架势磨损过快",非特效问题。
