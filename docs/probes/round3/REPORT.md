## 第8节：构建与运行、降级与限制

Windows / Java25 Gradle9.7.1 / Java8 Minecraft1.7.10 / Forge10.13.4.1614 / GTNH2.0.33，没有升级依赖。所有源集只通过显式init script启用：`tools/probes2/s1d`、`s2c`、`s3supp`。各短报告含命令、真实日志、被测jar版本、源码hash与设计影响。新建独立世界、只绑定localhost，EULA已由用户接受。

S1d是实际WorldServer、牛与真实EntityPlayerMP的原版伤害/事件夹具，MP未网络登录；换维度/下线生命周期用真实事件类型测试，不冒称完整联网路径。S2c四场真实专用服+单客户端；S3b七场有效专用服+双客户端。最终12场有效专用服务器exit=0，所测客户端/OpenGL类加载均0；S2c四场客户端exit=0。S3客户端退出/清理由runner管理，未单独记录全部客户端exit数值。

所有实验 `check` 首次通过（3s，29tasks）；最终实验jar与check合并通过（10s，30tasks）；普通 `build`：BUILD SUCCESSFUL in703ms，24tasks，见 [检查](evidence/round3-final-check.log)、[普通构建](evidence/round3-normal-build.log)。JUnit仍NO-SOURCE，未用构建代替运行验收。[隔离验证](evidence/final-verification.json)证实相对最新work主源码/生产构建配置diff为空、生产发布/dev/sources三个jar无实验条目。

S1d无瞬时字段修改、无伤害队列、无静默取消递归；ASM/Mixin未采用。S2c不接管C03，不做自制扫掠；墙由原生processPlayer，END仅累计预算。S3b使用网络意图journal与同一短锁定义到达/提交顺序，世界结算仍在游戏线程；该实验接入与旧FML队列差异明确说明，生产安全校时/协议未完成。

部分最终源与完整矩阵被测jar有仅夹具/日志版本差异，报告分别记录，不伪称所有矩阵在最后编译产物重新运行。S3最终日志清理后resolve指令与边界被测jar相同，见 [不变量总计](evidence/guard-all-invariants.json)。原生日志保留开发签名、版本检查、OpenAL等警告；初次300ms客户端未登录的超时场次不纳入验收，修正目录准备后新label完整复跑，根因未单独证明。

## 设计影响与优先级

用户已接受S1d对所有来源缩短无敌帧，优先于旧模块的瞬时隔离候选；不再尝试S1b/S1c方案。S1d支持持久目标状态方向，但应写明旧timer过渡、同值外部写入无法辨识及真正联网生命周期后验。

S2c支持真实单调经过时间的累计预算；补充准备传送握手、余量与声明总距离上限。原版墙拦截不能归功于END，未声称最终坐标预算保护所有tick内中间位置。

S3b按审核后的不变量口径通过，旧提前量桶配额不作为本轮阻塞。原型说明1.1/S3“延期2约覆盖单程100ms”须加稳定TPS/按下相位条件；真实逻辑tick不保证50ms物理跨度。若要求最低物理等待需另审，不擅自改双截止方案。

模块“原稿细节保留”全部保留。数值仍可配置，没有冻结公开API，没有以连点加技能替代完整攻击流；SA、模式、切上/空中追击、第二武器、正式美术保持后置。全部探针有结论，等待审核。

## 审核结论（用户审核后补记）

- 三项均接受通过，入口条件满足；P0 的必带条件写在[原型说明 1.2](../../design/proposals/prototype-spec-v1.md)，核心包括：交锋目标缩短 `maxHurtResistantTime` 的归属与恢复、位移预算的灵敏度与叠加、格挡改为默认延后 3 tick 并加墙钟双约束、生产校时与端到端反馈。
- S3b 的不变量是接入正确性的验证，不等于玩家在高延迟下的可用性；后者取决于真实按键时机，需 P0 实测。
- S2c 的结果证明无误纠正与粗暴违规被拉回，没有测量“略超速”的检出灵敏度，已列入 P0 必带条件。
- 友好实体误击保护与平时态方块右键放行为用户已决定的默认值。
- 探针代码保存在分支 `probe/round3-budget-damage`（提交 `a7f28c9`），不在 `work`。
