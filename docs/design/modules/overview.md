# 项目定位与体验目标

> 整理日期：2026-10-08。当前讨论入口；已确认方向与提案分别标明，尚未实现或验证。
> 状态总表：[设计状态](../design-status.md)。原稿章节：[V1.0 设计对照](../archive/v1.0/overview.md)。

## 当前方向

Clashweave 是面向 Minecraft 1.7.10 的全新独立动作战斗模组，并以可扩展框架组织不同武器和战斗风格。用户已选择融合型战斗和第一、第三人称完整支持。

SlashBlade 提供早期灵感，但其代码、API、按键、单刀技能槽和资源公式均不是项目约束。日本刀与居合作为首套设计内容；框架应允许后续长枪、长剑、拳术等采用不同的规则。

用户进一步强调首套内容按原稿的拔刀剑术展开，保留轻重击、切上挑飞、空中追击和纳刀态居合。内容定义见[日本刀模块](katana.md)，避免精简输入时失去首套武器身份。

## 玩家体验目标

用户进一步明确核心目标：战斗操作简单，需要玩家做决策与博弈，并在交锋基础上拥有好看的技能。此目标是后续取舍标准；下面的实现方式仍为设计建议，不等于已确定按键或招式。

| 目标 | 设计应做到 |
| --- | --- |
| 操作简单 | 少量固定意图即可完成攻防，基础连招容易打出，紧急防御不靠复杂指令 |
| 决策与博弈 | 距离、时机、继续/派生/退出具有不同收益和可理解风险，对手能回应 |
| 技能好看 | 基础动作本身有表现力，特殊节点提供更鲜明的动作和反馈，融入交锋 |

建议技能上限来自选择质量，而不是必须按完长指令才能使用核心能力。普通玩家应能较早体验特殊动作，熟练玩家则更会选择发动时机与衔接路线。

基础招式与 SA 都需要可观察的准备、有效与恢复阶段。华丽效果保持攻击方向、威胁和反击机会可读，避免长时间不可操作的演出或遮满目标的光效。

用少量可辨识输入完成完整交锋，保留观察、距离、时机、攻防与路线选择。减少按键不能把攻击流缩成自动连点加一个独立技能。

基础战斗与常态 SA 在没有爆气时仍完整可用；整体流程特化、爆气后武器/使用者形态专属动作是待审查的能力方向。爆气辅助战斗或提供模式入口。锁敌降低持续瞄准负担，鼠标保留观察控制。

核心循环仍采用原讨论的体验目标：观察与调整距离 → 交锋与争夺主动权 → 创造破绽 → 衔接攻击或特殊能力 → 收束、退出或重新交锋。它不是强制阶段状态机，普通攻击可以直接造成生命伤害。

## 继承的架构基线（待验证）

战斗规则、内容和客户端表现分开；玩家与 AI 经过统一动作调度；风格以组合方式配置动作图、运动、防御和能力。双视角共享战斗规则，不能因镜头设置改变攻击范围与伤害。

## 尚待明确

首套内容的最小攻击流、原版探索交互的边界、模式的具体价值，以及第二套武器的验证范围。复杂技术模块必须服务已经明确的玩家体验。

## 原稿细节保留（设计基线，非实现承诺）

以下恢复原稿的具体设计内容，未被明确修改的机制继续作为继承提案，不因整理或精简操作而删除。数值、代码、接口、默认配置及技术断言仍需验证；本模块前文列出的用户调整优先。已调整的键位、单 SA 限制与三类爆气在摘录中改为当前边界，原文仍完整保留。

## 第一部分：项目定位与设计目标

### 1.1 项目概述

Clashweave 旨在为 **Minecraft 1.7.10** 构建全新的、独立于 SlashBlade 的动作战斗框架，不依赖 SlashBlade，也不需要兼容原有拔刀剑 API 或附属刀剑。第一套内容选用打刀及日式剑术；引擎本身应能支持未来的长枪、大剑、双刀、拳术和其他战斗风格。

设计参考并非直接复刻，而是吸收各作品的机制特点：

| 参考作品 | 借鉴思想 | 在本项目中的使用方式 |
|---|---|---|
| SlashBlade | 拔刀、高速连斩、空中追击 | 打刀内容层的动作风格 |
| Devil May Cry | 连段派生、动作取消、视觉华丽性 | 多入口动作图和追击选择 |
| Sekiro | 姿态压制、攻防节奏、精准反击 | 防御与崩势机制 |
| The King of Fighters | 资源与爆发时机 | 参考来源，具体爆气用法重审 |
| 死神 VS 火影 | 资源消费、变身与战斗节奏 | 参考来源，具体用法重审 |
| Guilty Gear | 资源取舍与攻防转换 | 参考来源，不直接继承共享消费方案 |

**定位不是将 Minecraft 改造成纯格斗竞技场。** 探索、挖掘、方块交互、生存和多人合作应继续自然运行。

### 1.2 产品与引擎分层

```text
Clashweave
├── Combat Framework
│   ├── 输入意图、输入缓冲与动作选择
│   ├── 动作图、分层状态与时间轴
│   ├── 防御、崩势、位移、命中和伤害
│   ├── SA、Burst、资源与连招预算
│   └── 多人网络同步及权威判定
├── Presentation Framework
│   ├── 第一人称武器和手部动画
│   ├── 第三人称全身动画
│   ├── 相机与目标辅助
│   ├── HUD、音效、刀光和命中反馈
│   └── 动画资源管线
├── Combat AI
│   ├── 感知、距离与局势评估
│   ├── 战术决策和虚拟输入
│   └── 可调整的反应能力
└── Combat Content
    ├── 第一套打刀 Combat Style
    ├── 招式、SA、Burst Profile
    └── 后续武器、流派和附属内容包
```

Combat Framework 决定规则；Presentation Framework 决定玩家看到与听到什么；Combat Content 决定一类武器如何使用框架能力。三者不能互相形成隐藏依赖。

### 1.3 六条不可妥协的原则

1. **简单操作、复杂决策。** 普通玩家能用轻攻击、重攻击、格挡、闪避完成战斗；高手依靠时机、间合、资源及连招路线取得优势。
2. **玩家保有控制权。** 输入缓冲和取消应让操作更顺手，不能让角色在玩家停手后继续执行一串过期指令。
3. **进攻、防御、移动都有明确价值。** 禁止无脑连点、无限格挡、无限浮空形成压倒性最优策略。
4. **SA、Burst 是改变局势的工具，不是替代基础战斗的伤害按钮。**
5. **双视角共享单一权威战斗结果。** 切换 F5 不改变命中、范围、时间窗口、伤害、资源或角色坐标。
6. **框架提供能力，不要求每把武器使用全部能力。** 长枪不一定有纳刀；格斗风格不一定有架势条；某些风格可以不支持 SA。

## 第二部分：实际战斗体验与交战循环

### 2.1 战斗循环

```text
观察 / 接近 → 试探 / 交锋 → 争夺先机
                                  │
                   ┌──────────────┴──────────────┐
                   ▼                             ▼
              创造对手破绽                   失去主动权
                   │                             │
              连招 / SA                     格挡 / 踏步
                   │                         / 合法反击
                   └──────────────┬──────────────┘
                                  ▼
                            重整 / 纳刀
                                  │
                             再次交锋
```

交战节奏包含三个可重叠层次：**基础交锋**（攻防、距离与时机）、**高速追击**（崩势、浮空、取消）、**爆发重整**（SA、爆气、恢复）。它们不是强制的四阶段状态机；玩家可以在未崩势时连击，也可以提前收刀结束追击。

### 2.2 普通 Minecraft 实体的兼容层级

| 等级 | 适用对象 | 能力范围 |
|---|---|---|
| Tier 0 | 原版普通实体和多数模组实体 | 接受新攻击、伤害、击退及必要的受击反馈 |
| Tier 1 | 强化战斗实体 | 有硬直、崩势、抗浮空与部分防御行为 |
| Tier 2 | 玩家、专用剑术敌人、Boss | 使用完整动作图、攻防、SA、Burst 与资源决策 |

玩家不应为了使用刀而必须将全部原版怪物替换成特殊 AI。普通生存仍然能够正常进行。
