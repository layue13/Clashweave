# 首套内容：日本刀与拔刀剑术

> 更新日期：2026-10-08。用户要求回到原稿的轻重击、挑飞与拔刀术设计；具体输入、窗口和参数尚未实现或验证。
> 来源：[原稿基础剑术](../archive/v1.0/actions.md)与[原稿攻防追击](../archive/v1.0/defense.md)。框架规则见[动作](actions.md)、[防御](defense.md)、[SA](sa.md)、[输入](input.md)。

## 1. 内容方向

首套战斗内容围绕日本刀、居合拔刀、间合、攻防衔接与纳刀重整，结合高速动作游戏的特殊派生和空中追击。这里是游戏化剑术设计，不将挑飞、幻想 SA 或整套连招当作真实拔刀术的技术规范。

框架仍然通用，但首套内容要有明确身份，不能在精简输入时抽象成没有武器特色的“攻击 + 技能”。其他武器不强制继承纳刀、居合或同样动作。

## 2. 恢复并保留的动作类别

| 类别 | 原稿内容 | 设计作用，具体平衡待定 |
| --- | --- | --- |
| 居合拔刀 | 纳刀态的居合一闪 | 观察间合、选择拔刀出手时机，打开后续进攻 |
| 轻攻击 | 横一文字、返刃、逆袈裟等 | 快速试探与持续衔接，灵活组织路线 |
| 重攻击 | 袈裟重斩等压制动作 | 更大动作承诺，争取压制/崩势收益 |
| 切上挑飞 | 原稿返刃后重攻击切上 | 在合法机会制造空间转换，进入有限空中追击 |
| 位移攻击 | 踏步斩、后撤斩 | 接近、追击与调整间合 |
| 空中追击 | 空中轻击、返刃、追击斩/SA | 高速与华丽表现，保留控制保护和收束出口 |
| 纳刀 | 回到准备状态的收势动作 | 结束当前进攻、准备下一次拔刀，不是无成本取消器 |
| SA | 独立、连招、反击、追击和终结入口 | 特殊战术动作与表现，连接在剑术流中 |

轻重击是需要保留的动作和决策区分，是否分别占用独立物理键仍待设计。切上可以是重攻击在特定节点的派生，不必另加“挑飞键”。

## 3. 武器状态

纳刀态与拔刀态来自原稿，是首套内容需要继续展开的核心状态：

- 纳刀态：保留观察与移动，合法攻击入口可执行居合拔刀。
- 拔刀态：轻重攻击、位移斩、格挡、SA 等构成持续交锋。
- 纳刀过程：具有准备、恢复和合法转换约束，不能反复切状态免费躲掉出招风险。

主动纳刀应作为可选择的战术节点继续设计，具体入口未定。脱离交锋的自动收势可作便利功能候选，但不能直接替代战斗内居合准备的选择。

## 4. 原稿路线与本轮整理

原稿已有以下关系，保留其路线意图，不固定原时间数值和 F/R/V 等键位：

```text
纳刀态 → 居合一闪
           ├─ 轻 → 横一文字 → 轻 → 返刃
           │                         ├─ 轻 → 逆袈裟 / 收束
           │                         └─ 重 → 切上（满足挑飞条件）
           │                                  └─ 有限空中追击 → SA / 落地收束
           ├─ 重 → 袈裟压制
           ├─ 合法 SA 派生 → 转换 / 追击 / 终结
           └─ 合法收势 → 纳刀准备

拔刀空闲 → 轻 / 重 / 合法独立 SA / 纳刀
```

“轻、重、SA 派生、纳刀”在图中表达意图，不表示已经确定四个专用按钮。图中的新增收束与 SA 位置用于说明完整路线，具体边与条件还需逐节点确认。锁敌只帮助有界对准，不能自动选择轻重或追踪挑飞目标。

## 5. 决策与机会

轻攻击适合试探和衔接；重攻击的较大收益要伴随可观察的承诺与恢复。玩家可以在轻击之后继续、安全收束或投入重击，不以“重必定赢防御”等硬规则替代距离和时机。

挑飞不是所有重击的无条件效果。具体机会可以由崩势或某种已确认的命中状态开放，尚未确定；对方仍受有限控制预算保护，空中 SA 与爆气不能清空保护重新无限连。

纳刀重新准备、地面压制和空中追击应形成不同路线，不能让挑飞成为每次进攻的唯一正确答案。具体收益需比较多目标、生存怪物与 1v1。

## 6. 操作设计的任务

用户最新倾向是装配不同 SA 的同类日本刀，基础居合、轻重、切上和纳刀主体相近，由 SA 附加效果与特殊派生。按此方向先建立稳定剑术骨架，再设计各能力特色；整体重做动作图不作为每项 SA 的默认前提。

用户提出 SA 可整体特化攻击流，部分能力在爆气后改变武器/使用者形态，例如踏步变瞬移；这作为待审查提案，不是定案。首套剑术可以在保留居合、轻重和纳刀决策的基础上采用专属动作图与形态动作，具体能力及形态清单未定；不把原稿招式名固定为所有形态唯一动作。

以这套动作身份推导简单操作，优先解决轻重意图、防御/回避和纳刀准备的可辨识入口；每项 SA 仍融入可理解的节点，不先堆专用键。

接下来应补齐各节点的可选边、命中/挥空差异、挑飞机会、取消与收束，再比较输入布局。轻重击保留，不等于已经选择左右键轻重或长按蓄力。

## 本轮收益方案（已接受为原型基线，待验证）

建议纳刀付出准备时间，换取下一次居合的前向间合与抢恢复机会；近身轻斩保留持续衔接价值。不加必须维持的纳刀增伤层数，不免费清后摇或回满架势。首个架势对战样例先在崩势窗口开放切上，与地面继续/终结和收势比较。详细理由与其他模块配合见[综合推荐](../proposals/combat-recommendation-v1.md)。

### 4.1 打刀的两种武器状态

- **纳刀态（Sheathed）**：允许移动、踏步、观察及合法防御。轻攻击意图可直接触发居合拔刀。
- **拔刀态（Drawn）**：可以使用持续轻/重攻击、格挡、SA 与连招派生。以明确纳刀意图进入收势，纳刀本身是一段受时间轴约束的动作。

高速切换纳刀不能用于任意取消所有攻击后摇。打刀拥有纳刀行为是内容规则，不是核心引擎对所有武器的要求。
