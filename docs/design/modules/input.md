# 输入与原版交互

> 整理日期：2026-10-08。当前讨论入口；已确认方向与提案分别标明，尚未实现或验证。
> 状态总表：[设计状态](../design-status.md)。原稿章节：[V1.0 设计对照](../archive/v1.0/input.md)。

> 综合方案已接受作为原型基线，键位仍需测试。本次完善新增 V 主动特殊入口的审核候选，并按“交锋态/平时态”放行原版潜行与方块交互，具体行为见[原型说明](../proposals/prototype-spec-v1.md)。旧布局保留对照，不同时启用冲突绑定。

## 已确认要求

用户要求从第一性原理重新设计操作，指出旧键位过多；允许锁敌，并认可弱跟随和可选的锁敌后自动第三人称。SA 必须融入操作，不能简化为单一独立技能按钮。

## 当前设计工作

轻攻击、重攻击、纳刀准备及挑飞追击已在[日本刀内容](katana.md)恢复为需要支持的路线。当前任务是减少表达这些选择的操作负担；不能把“是否需要独立键位”误写成“是否保留该战术动作”。挑飞可由既有重击派生到达，无需默认专用键。

先列出玩家需要表达的选择：目标、距离、攻击路线、防御、回避与模式激活，再给这些意图分配物理输入。[动作模块](actions.md)负责路线，[SA 模块](sa.md)负责特殊能力入口，[视角模块](presentation.md)负责相机。

未锁敌时，鼠标控制观察与期望瞄准。锁敌后，目标选择帮助攻击对准，鼠标仍能观察周围；WASD 相对目标接近、后退与环绕属于当前候选。锁敌不能保证命中或绕过动作转向限制。

物理输入与动作定义分开，不把某个键硬编码为某把刀的特定招式。候选的“继续、派生”语义可以连接普通动作和 SA，但并非已经确定只需要两个进攻意图。

## 布局候选，均未定稿

| 候选 | 收益 | 必须解决的问题 |
| --- | --- | --- |
| 左键进攻、右键防御，加通用派生输入 | 高频攻防直接，接近原生习惯 | 派生是否能边移动边完成；多个分支如何区分 |
| 左右键承载两种进攻意图，防御独立输入 | 鼠标表达更多路线选择 | 紧急防御是否容易操作，键盘手是否过载 |

中键锁敌、独立回避、低频模式输入是待评估布局元素。Q、F、Shift 等上一轮示例不是最终默认键位。长按、双击和修饰键也有时延与同时操作成本，不能只按键位数评价。

## 重击放在哪里（上一轮比较基准，未定案）

用户认可原稿，并询问重击是否适合长按左键。原稿是左键轻击、右键防御、F 重击。本轮建议先用这三个输入作为比较基准：轻重都是高频路线选择，防御需要及时响应；减少 SA 等专用键不等于必须把轻重合并成一种手势。F 尚未确认为最终默认，可重绑定，鼠标侧键可作个人选择但不能作为硬件前提。

重击与蓄力是不同概念：重击可以按下即请求，仍承担招式前摇；蓄力是动作开始后继续投入时间、延后释放。不能为了省键把所有切上、压制与终结派生都改成必须蓄力。

| 长按左键的解释 | 收益 | 代价与边界 |
| --- | --- | --- |
| 短按松开轻击，长按进入重击准备 | 单键表达轻重 | 轻击要等松开才能确定，按住期间必须有清楚准备反馈 |
| 按下立即轻击，持续按住请求下一段重击 | 轻击响应及时，可简化部分轻转重衔接 | 当前已经出轻击，不是独立重击；下一段只能在合法窗口执行，仍需独立重击入口或接受路线变化 |
| 按下共同准备，按住时转入重击 | 可以在准备阶段辨别意图 | 需重新设计轻击前摇、转换窗口和成本；不能在轻击已结算后追溯换成重击 |

因此暂不推荐把长按左键作为唯一重击入口。长按可用于明确的蓄力动作，例如某种居合准备，但不是所有居合都必须长按；也可以测试为可选简化布局，需同时检验独立重击、轻重分支、挑飞与终结是否仍能准确表达。

保留 F 的代价是键盘手承担更多操作，尤其食指从 D 移到 F 时的右移冲突，必须在环绕移动中检验。若这一代价明显，可对比左键轻击、右键重击、独立防御输入的布局；右键已承担防御时不能直接再绑重击，防御必须另有及时、明确的入口。具体防御键、长按阈值及默认布局继续待定。

## 人体工学优先的布局建议（原型基线，待体验验证）

用户要求符合人体工学。按常见 WASD 手位，建议优先让高频攻防与移动分配给不同手指，而非只减少键位数量。因此本轮将左右键轻重、左 Shift 防御、左 Alt 回避作为优先试验布局，上一轮 F 重击/右键防御保留作比较。这是基于手指分工的设计判断，尚未经过玩家测试，不宣称适合所有手型与键盘。

常见手位下，无名指负责 A，中指负责 W/S，食指负责 D；左右鼠标键分别承载轻重选择，小指按左 Shift，拇指按左 Alt 或空格。这样基础攻击、防御与回避较少需要食指离开 D 或无名指离开 A。前进与后退本身仍共享中指，不宣称能同时完成所有物理输入。

防御按下立即产生请求，持续按住维持合法格挡；是否执行由动作窗口决定，不因此允许任意攻击取消。左 Alt 按下请求一次回避，方向来自 WASD，长按不自动重复回避。精准格挡不等待长按分类，轻重不使用双击分类，跳跃也不因战斗状态直接改成回避。

主要代价：持续按 Shift 可能使小指疲劳；左 Alt 的位置随键盘和拇指习惯而异，跳跃与回避也共享拇指。需要测试跳跃后空中回避的衔接，不能要求玩家同时按住空格和 Alt 才能启动普通回避。中键按压力和误滚动也需测试。所有操作允许重绑定，鼠标侧键提供便利但不是使用前提；辅助防御切换模式可评估，但不能反复自动刷新精准格挡窗口。

R 纳刀与 B 模式暂作比较键位。只有实际使用较少时，较大的手指移动才较可接受；若主动纳刀成为频繁的居合循环入口，应重新评估其位置，不能先把它当作低频整理动作。SA 附加效果沿基础动作触发，主动 SA 与独立/反击等入口继续保留：先检查哪些可以由明确轻重派生表达，必须额外区分的再安排通用派生输入，不用自动选招掩盖映射缺口。

本布局接管 Shift 后会与潜行冲突，右键也与物品使用冲突。持有支持该系统的武器即启用战斗映射，不再要求额外进入战斗按键。持刀时尽量接管键位，并按“交锋态/平时态”放行原版潜行与方块右键交互，不设 F 临时交互键；持刀时左键始终是攻击、对实体的右键始终是重击入口，不放行挖掘与实体交互（用户决定）。尚未经体验验证，具体见原型说明第 3 节。

## 当前键位汇总（最新候选，尚未完整定稿）

本表汇总原稿与后续讨论，区分当前推荐和仍待选择的键位。不是已经实现的默认设置，也不代表同时启用所有候选输入。

| 操作 | 当前键位或候选 | 状态 |
| --- | --- | --- |
| 轻击、常规衔接 | 左键点击 | 当前推荐；纳刀态可进入原稿居合入口 |
| 防御、精准格挡 | 左 Shift 按住 / 按下 | 最新提案；旧右键防御布局用于比较 |
| 重击、合法重击派生 | 右键点击 | 最新提案；旧 F 重击布局用于比较 |
| 踏步 / 回避 | 左 Alt＋方向 | 最新提案；旧 X/Shift 方案用于比较，需测试拇指舒适度 |
| 主动纳刀 / 收势 | R | 暂作比较键位；若使用频繁需重新评估 |
| 锁敌 / 解除 | 中键候选；原稿 G | 允许锁敌已确认，物理键位未定 |
| 爆气 / 模式激活 | 原稿 B | 候选；按当前模式定位设计，不恢复旧三类自动选类 |
| 主动 SA / 特殊派生 | V | 新审核候选；临时通用主动入口，Q 不叠加，不能自动猜测高成本技能 |
| 观察 / 自由瞄准 | 鼠标移动 | 保留；锁敌后仍能观察，遵守相机规则 |
| 移动、跳跃 | WASD、空格 | 保留基本职责；锁敌相对移动仍待验证 |
| 快捷栏、背包、视角 | 滚轮 / 数字键、E、F5 | 保留原版职责 |
| 战斗映射启用 / 原版交互恢复 | 持刀默认战斗；平时态放行潜行和方块右键交互；切到普通物品恢复 | 左键始终攻击、不挖掘，对实体不交互；状态按游戏状态判断并提示，不能绕过动作恢复 |

长按不是目前唯一重击入口，仅保留为明确蓄力动作或简化布局的候选。挑飞和终结优先通过合法重击/派生节点表达，不默认新增专键；SA 附着效果与主动特殊入口同时保留，主动入口不能靠目标血量或距离自动猜测。

过程资料曾用 F 表示模式激活，另有 F 重击方案；不能把它们当成同一布局同时启用。Q 派生、V SA 和旧 F 重击也不能未经动作图审查直接叠成三个相同用途的按键。所有最终键位须允许重绑定，侧键仅为便利选项。

## 原版交互边界

用户提出持刀时应覆盖大部分原版操作。建议由主手当前物品是否注册并启用 Combat Style 决定输入映射：持有受支持的战斗武器即可使用战斗操作，切到普通物品恢复原版行为。不是所有名称中带“剑”的物品都会自动接管，也不把锁敌作为启用条件。首套日本刀的纳刀态仍处于战斗映射，纳刀不等于退出系统。

持刀时，左键和右键稳定表达轻重攻击，Shift/Alt 按最新候选表达防御/回避；交锋态不因准星移到墙壁、箱子或友好实体上就自动改成交互；左键在任何状态都不改成挖掘。平时态（离开交锋超过阈值）才放行潜行和对可交互方块的右键。旧右键防御布局也遵循同一稳定映射原则。覆盖重点是与战斗争用的输入，移动、跳跃、快捷栏、背包和 F5 保留基本职责，Q 丢物等尚未被采用为战斗键的原版操作不无故取消。

原版交互的恢复途径：切到非战斗物品；平时态自动放行潜行与可交互方块的右键。对实体（含村民、动物）的交互不放行，持刀一律出刀。具体状态判定与输入清理见[原型说明](../proposals/prototype-spec-v1.md)第 3 节，仍需实际检验。

状态切换时清理残留按住状态，保持中的 Shift 不合成一次新的精准按下。状态需有可辨识提示；本设计尚未经运行验证。

滚轮快捷栏、背包、跳跃和视角切换尽量保持熟悉职责。GUI、换物品、死亡和维度变化要清理不再有效的输入；不能通过这些操作绕过权威动作恢复。

## 缓冲与确定性

输入只能在已声明的窗口执行，缓冲应有短寿命与覆盖规则。请求的派生失效后，不得偷偷改成另一 SA 并消费其资源。精准格挡以防御模块的时机规则判断，不能无限缓存。

## 待确认与验证

[S5 实测](../../probes/S5-input.md)确认包装原版移动提供器需同时撤销 sneak 与 0.3 移动倍率，所测 Shift/GUI/装备边沿回放通过；客户端 AI 目标未同步导致威胁误判，整体需改为权威交锋态同步方案。这个建议等待审核，尚未实现正式状态同步；人工舒适度与完整生命周期仍未验证。

按[原型说明](../proposals/prototype-spec-v1.md)的动作和输入候选检查移动中攻防、主动 SA、频繁纳刀、锁定多目标、贴墙、开箱、换武器和 F5。具体默认键、窗口与舒适度仍待审核/体验验证。

过程分析见[交互 V2](../proposals/interaction-v2.md)与[攻击流 V2](../proposals/attack-flow-v2.md)。

## 原稿细节保留（设计基线，非实现承诺）

以下恢复原稿的具体设计内容，未被明确修改的机制继续作为继承提案，不因整理或精简操作而删除。数值、代码、接口、默认配置及技术断言仍需验证；本模块前文列出的用户调整优先。已调整的键位、单 SA 限制与三类爆气在摘录中改为当前边界，原文仍完整保留。

### 3.2 抽象输入意图

底层不能写死 `if (leftClick && katana) ...`。输入处理的唯一职责是产生平台无关的动作意图：

```text
LIGHT_ATTACK  HEAVY_ATTACK  GUARD_PRESS  GUARD_RELEASE
DODGE         SPECIAL_ATTACK MODE_ACTIVATE SHEATHE
TARGET_LOCK   JUMP           MOVE_VECTOR
```

```text
键盘/鼠标/手柄/AI
      ↓
InputProvider（采样 Press / Hold / Release）
      ↓
CombatIntent（统一语义）
      ↓
Combat Style 的 ActionResolver
      ↓
ActionScheduler（合法性、时机、资源）
      ↓
ActionRuntime（权威执行）
```

同一个 `LIGHT_ATTACK` 对打刀可能是横斩，对长枪是突刺，对拳术是直拳。输入层不需要知道具体武器。

### 3.3 输入形式与缓冲

需要区分 Press、Hold、Release、Tap、方向＋Press 和 Buffered Press。按住右键连续格挡不等于反复触发新的精准格挡窗口。

| 意图 | 建议缓冲时间 | 规则 |
|---|---:|---|
| 轻攻击 | 4 tick | 同类别仅保留最近一次有效输入 |
| 重攻击 | 4 tick | 可以等待合法派生窗口 |
| SA | 4 tick | 缓冲时锁定申请的上下文类别 |
| 闪避 | 2 tick | 避免长时间后突然闪避 |
| 模式激活 | 2 tick（原型参考） | 只保留明确的激活请求，不自动改类别 |
| 精准格挡 | 不提前缓冲 | 依实际防御输入时机判断 |
| 纳刀 | 4 tick | 只在合法收刀窗口执行 |

缓冲不采用无限 FIFO。过期输入必须丢弃；当前动作被打断时，原本申请的“连招 SA”不能被自动改为“中立 SA”。资源不足的模式请求 不在后台保留等待资源补满。

### 3.4 Minecraft 原生交互的冲突解决

原稿提出 **情境模式** 和 **战斗专注模式** 两种方案，以下保留对比。当前原型基线采用持刀稳定战斗映射，显式临时交互候选见前文；本表不是并行默认规范：

| 准星/环境 | 情境模式左键 | 情境模式右键 |
|---|---|---|
| 空气 | 剑术攻击 | 防御 |
| 敌对实体 | 剑术攻击 | 防御 |
| 普通方块 | 原版挖掘（已被持刀决定否决：持刀左键始终攻击） | 按规则防御或物品使用 |
| 箱子、机器 | 原版挖掘 | 优先原版交互 |
| 友好实体 | 按 PvP / 友好攻击策略 | 优先原版实体交互 |
| GUI | 原版 GUI 输入 | 原版 GUI 输入 |

情境模式要考虑近墙战斗时准星指向墙壁的反常体验；战斗专注模式下，持有支持的武器时优先把左键解释为攻击，并预留可重绑定的“强制方块交互”输入（如潜行＋右键）。仅在该武器的 Combat Style 激活时接管输入；不持战斗武器时恢复原版行为。

不要仅靠 Forge 交互事件完成所有拦截：客户端按键、挖掘动作取消、服务端合法性分别处理，并验证 1.7.10 左右键事件在不同侧的行为。

### 3.5 方向攻击与目标辅助

方向修饰主要服务 **重攻击和踏步**，普通轻攻击不应因为一直按着 W 就意外变成突进斩。

| 输入 | 打刀示例 |
|---|---|
| 前方向＋重击意图 | 前进型重斩 / 突进斩 |
| 后方向＋重击意图 | 后撤斩 |
| 左方向＋重击意图 | 左侧切入斩 |
| 右方向＋重击意图 | 右侧切入斩 |
| 回避意图＋方向 | 对应方向踏步 |

不支持该方向分支时，应回退到明确定义的普通重击，而不是随机选择相似动作。默认仅使用弱目标辅助：小角度修正攻击方向，不强行旋转摄像机。锁定输入可开启手动锁定并提供环绕移动；锁定不允许越墙自动命中或瞬间转身 180°。
