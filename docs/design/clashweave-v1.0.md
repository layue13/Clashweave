# 第一部分：项目定位与设计目标

## 1.1 项目概述

Clashweave 旨在为 **Minecraft 1.7.10** 构建全新的、独立于 SlashBlade 的动作战斗框架，不依赖 SlashBlade，也不需要兼容原有拔刀剑 API 或附属刀剑。第一套内容选用打刀及日式剑术；引擎本身应能支持未来的长枪、大剑、双刀、拳术和其他战斗风格。

设计参考并非直接复刻，而是吸收各作品的机制特点：

| 参考作品 | 借鉴思想 | 在本项目中的使用方式 |
|---|---|---|
| SlashBlade | 拔刀、高速连斩、空中追击 | 打刀内容层的动作风格 |
| Devil May Cry | 连段派生、动作取消、视觉华丽性 | 多入口动作图和追击选择 |
| Sekiro | 姿态压制、攻防节奏、精准反击 | 防御与崩势机制 |
| The King of Fighters | 资源驱动的连招取消与爆发 | 进攻 Burst |
| 死神 VS 火影 | 受击脱困、战斗节奏转折 | 防御 Burst |
| Guilty Gear | 进攻资源与脱困资源之间的取舍 | 共享 Burst 资源池 |

**定位不是将 Minecraft 改造成纯格斗竞技场。** 探索、挖掘、方块交互、生存和多人合作应继续自然运行。

## 1.2 产品与引擎分层

```text
Clashweave
├── Combat Framework
│   ├── 输入意图、输入缓冲与动作选择
│   ├── 动作图、分层状态与时间轴
│   ├── 防御、崩势、位移、命中和伤害
│   ├── SA、Burst、资源与连招预算
│   └── 多人网络同步及权威判定
├── Presentation Framework
│   ├── 第一人称武器和手部动画
│   ├── 第三人称全身动画
│   ├── 相机与目标辅助
│   ├── HUD、音效、刀光和命中反馈
│   └── 动画资源管线
├── Combat AI
│   ├── 感知、距离与局势评估
│   ├── 战术决策和虚拟输入
│   └── 可调整的反应能力
└── Combat Content
    ├── 第一套打刀 Combat Style
    ├── 招式、SA、Burst Profile
    └── 后续武器、流派和附属内容包
```

Combat Framework 决定规则；Presentation Framework 决定玩家看到与听到什么；Combat Content 决定一类武器如何使用框架能力。三者不能互相形成隐藏依赖。

## 1.3 六条不可妥协的原则

1. **简单操作、复杂决策。** 普通玩家能用轻攻击、重攻击、格挡、闪避完成战斗；高手依靠时机、间合、资源及连招路线取得优势。
2. **玩家保有控制权。** 输入缓冲和取消应让操作更顺手，不能让角色在玩家停手后继续执行一串过期指令。
3. **进攻、防御、移动都有明确价值。** 禁止无脑连点、无限格挡、无限浮空形成压倒性最优策略。
4. **SA、Burst 是改变局势的工具，不是替代基础战斗的伤害按钮。**
5. **双视角共享单一权威战斗结果。** 切换 F5 不改变命中、范围、时间窗口、伤害、资源或角色坐标。
6. **框架提供能力，不要求每把武器使用全部能力。** 长枪不一定有纳刀；格斗风格不一定有架势条；某些风格可以不支持 SA。

# 第二部分：实际战斗体验与交战循环

## 2.1 战斗循环

```text
观察 / 接近 → 试探 / 交锋 → 争夺先机
                                  │
                   ┌──────────────┴──────────────┐
                   ▼                             ▼
              创造对手破绽                   失去主动权
                   │                             │
              连招 / SA                     格挡 / 踏步
                   │                         / 防御爆气
                   └──────────────┬──────────────┘
                                  ▼
                            重整 / 纳刀
                                  │
                             再次交锋
```

交战节奏包含三个可重叠层次：**基础交锋**（攻防、距离与时机）、**高速追击**（崩势、浮空、取消）、**爆发重整**（SA、爆气、恢复）。它们不是强制的四阶段状态机；玩家可以在未崩势时连击，也可以提前收刀结束追击。

## 2.2 普通 Minecraft 实体的兼容层级

| 等级 | 适用对象 | 能力范围 |
|---|---|---|
| Tier 0 | 原版普通实体和多数模组实体 | 接受新攻击、伤害、击退及必要的受击反馈 |
| Tier 1 | 强化战斗实体 | 有硬直、崩势、抗浮空与部分防御行为 |
| Tier 2 | 玩家、专用剑术敌人、Boss | 使用完整动作图、攻防、SA、Burst 与资源决策 |

玩家不应为了使用刀而必须将全部原版怪物替换成特殊 AI。普通生存仍然能够正常进行。

# 第三部分：操作系统与输入语义

## 3.1 默认按键

| 输入 | 默认行为 | 设计目的 |
|---|---|---|
| 鼠标左键 | 轻攻击 / 常规连招 | 高频基本输入 |
| 鼠标右键按住 | 防御；按下初期可精准格挡 | 与常见持剑防御习惯一致 |
| F | 重攻击 / 特殊派生 | 提供破势及方向分支 |
| V | 当前武器的 SA | 单独且稳定的语义 |
| B | Burst 爆气 | 紧急脱困与节奏转折 |
| X＋WASD | 踏步 / 闪避方向 | 调整间合 |
| R | 拔刀 / 纳刀 | 打刀内容特色 |
| G | 目标锁定开关 | 可选的目标辅助 |
| WASD | 移动及少量方向修饰 | 保持 Minecraft 原有操作 |
| 空格 | 跳跃 | 保持原版习惯 |
| F5 | 第一、第三人称切换 | 兼容原版使用习惯 |

所有按键必须允许重绑定。F、V、B、X、R、G 只是默认候选；安装其他模组后应能在设置页看到冲突。

## 3.2 抽象输入意图

底层不能写死 `if (leftClick && katana) ...`。输入处理的唯一职责是产生平台无关的动作意图：

```text
LIGHT_ATTACK  HEAVY_ATTACK  GUARD_PRESS  GUARD_RELEASE
DODGE         SPECIAL_ATTACK BURST        SHEATHE
TARGET_LOCK   JUMP           MOVE_VECTOR
```

```text
键盘/鼠标/手柄/AI
      ↓
InputProvider（采样 Press / Hold / Release）
      ↓
CombatIntent（统一语义）
      ↓
Combat Style 的 ActionResolver
      ↓
ActionScheduler（合法性、时机、资源）
      ↓
ActionRuntime（权威执行）
```

同一个 `LIGHT_ATTACK` 对打刀可能是横斩，对长枪是突刺，对拳术是直拳。输入层不需要知道具体武器。

## 3.3 输入形式与缓冲

需要区分 Press、Hold、Release、Tap、方向＋Press 和 Buffered Press。按住右键连续格挡不等于反复触发新的精准格挡窗口。

| 意图 | 建议缓冲时间 | 规则 |
|---|---:|---|
| 轻攻击 | 4 tick | 同类别仅保留最近一次有效输入 |
| 重攻击 | 4 tick | 可以等待合法派生窗口 |
| SA | 4 tick | 缓冲时锁定申请的上下文类别 |
| 闪避 | 2 tick | 避免长时间后突然闪避 |
| Burst | 2 tick | 仅对当时合法的 Burst 类别处理 |
| 精准格挡 | 不提前缓冲 | 依实际防御输入时机判断 |
| 纳刀 | 4 tick | 只在合法收刀窗口执行 |

缓冲不采用无限 FIFO。过期输入必须丢弃；当前动作被打断时，原本申请的“连招 SA”不能被自动改为“中立 SA”。资源不足的 Burst 不在后台保留等待资源补满。

## 3.4 Minecraft 原生交互的冲突解决

默认采用 **情境模式**，可开启 **战斗专注模式**：

| 准星/环境 | 情境模式左键 | 情境模式右键 |
|---|---|---|
| 空气 | 剑术攻击 | 防御 |
| 敌对实体 | 剑术攻击 | 防御 |
| 普通方块 | 原版挖掘 | 按规则防御或物品使用 |
| 箱子、机器 | 原版挖掘 | 优先原版交互 |
| 友好实体 | 按 PvP / 友好攻击策略 | 优先原版实体交互 |
| GUI | 原版 GUI 输入 | 原版 GUI 输入 |

情境模式要考虑近墙战斗时准星指向墙壁的反常体验；战斗专注模式下，持有支持的武器时优先把左键解释为攻击，并预留可重绑定的“强制方块交互”输入（如潜行＋右键）。仅在该武器的 Combat Style 激活时接管输入；不持战斗武器时恢复原版行为。

不要仅靠 Forge 交互事件完成所有拦截：客户端按键、挖掘动作取消、服务端合法性分别处理，并验证 1.7.10 左右键事件在不同侧的行为。

## 3.5 方向攻击与目标辅助

方向修饰主要服务 **重攻击和踏步**，普通轻攻击不应因为一直按着 W 就意外变成突进斩。

| 输入 | 打刀示例 |
|---|---|
| W＋F | 前进型重斩 / 突进斩 |
| S＋F | 后撤斩 |
| A＋F | 左侧切入斩 |
| D＋F | 右侧切入斩 |
| X＋WASD | 对应方向踏步 |

不支持该方向分支时，应回退到明确定义的普通重击，而不是随机选择相似动作。默认仅使用弱目标辅助：小角度修正攻击方向，不强行旋转摄像机。G 可开启手动锁定并提供环绕移动；锁定不允许越墙自动命中或瞬间转身 180°。

# 第四部分：基础剑术系统

## 4.1 打刀的两种武器状态

- **纳刀态（Sheathed）**：允许移动、踏步、观察及合法防御。左键可直接触发居合拔刀。
- **拔刀态（Drawn）**：可以使用持续轻/重攻击、格挡、SA 与连招派生。按 R 纳刀，纳刀本身是一段受时间轴约束的动作。

高速切换纳刀不能用于任意取消所有攻击后摇。打刀拥有纳刀行为是内容规则，不是核心引擎对所有武器的要求。

## 4.2 基础动作初始数值

| 招式 | 前摇 | 有效 | 后摇 | 战术用途 |
|---|---:|---:|---:|---|
| 横一文字 | 4t | 2t | 7t | 标准横斩 |
| 返刃 | 3t | 2t | 7t | 快速连招衔接 |
| 袈裟斩 | 5t | 3t | 9t | 高崩势压制 |
| 逆袈裟 | 4t | 2t | 8t | 向上衔接 |
| 切上 | 5t | 2t | 10t | 条件浮空 |
| 踏步斩 | 5t | 2t | 9t | 接近与追击 |
| 居合一闪 | 5t | 2t | 10t | 纳刀起手、时机反击 |
| 后撤斩 | 4t | 2t | 9t | 脱离近距离 |
| 纳刀 | 8t | — | — | 武器状态切换 |

20 TPS 下 1 tick 理论时长为 50ms。以上均为**原型测试值**，需结合动画可读性、多人 RTT、普通玩家的操作节奏调整。

## 4.3 第一版动作图

```text
纳刀 ──LIGHT──> 居合一闪
                    ├──LIGHT──> 横一文字 ──LIGHT──> 返刃
                    │                           ├──LIGHT──> 逆袈裟
                    │                           └──HEAVY──> 切上
                    ├──HEAVY──> 袈裟斩
                    └──SHEATHE──> 纳刀

拔刀空闲 ──LIGHT──> 横一文字
            ├──HEAVY──> 袈裟斩
            ├──SPECIAL──> 中立 SA
            └──SHEATHE──> 纳刀
```

左键连点能打出稳定基础连招；高手使用 F、X、V、B 在窗口内主动改变路线。连招不是“攻击次数增加一就固定跳下一招”的死树，而是条件驱动的有向图。

## 4.4 取消类型与基本约束

| 类型 | 条件 | 限制 |
|---|---|---|
| 连招取消 | 到达招式定义的窗口 | 不代表可以取消任意前摇 |
| 命中取消 | 服务端确认命中或合格交互 | 挥空不自动获得同等权限 |
| 防御取消 | 当前动作显式允许 | 不允许所有攻击任意变格挡 |
| 闪避取消 | 当前动作允许、满足资源条件 | 仍需碰撞和位移验证 |
| SA 取消 | 动作图存在合法边 | 需要资源、结果及窗口检查 |
| Burst 取消 | 消耗爆气并符合 Burst Profile | 不能任意绕过防作弊规则 |

以横斩为例，时间轴 `[0,4)` 前摇、`[4,6)` 有效、`[6,13)` 恢复；命中后可在 `[7,11)` 连招取消，挥空可能只在更晚窗口允许重新行动。所有窗口采用**左闭右开**定义。

# 第五部分：攻防、间合与崩势

## 5.1 三种防御结果

| 结果 | 条件 | 效果 |
|---|---|---|
| 普通格挡 | 正确方向、非精准时间窗 | 降低伤害、消耗架势、存在格挡硬直 |
| 精准格挡 | 接触时处于短暂精准窗口 | 减少架势损失、缩短硬直、开放反击 |
| 防御失败 | 方向错误、不可防御或窗口外 | 正常受击 |

按下右键进入防御，初始前 **3 tick** 为精准格挡窗口；继续按住是普通格挡，松开退出。重复点按不能无限刷新精准窗口，需要再防御限制与明确的硬直规则。

第一版以**正面约 140° 扇区**作为普通格挡测试参数。精准格挡主要赢得动作帧优势，不必直接把对方打崩势；更复杂的方向性防御留给后续武器风格。

## 5.2 间合与攻击路径

攻击命中应考虑距离、朝向、实际刀刃轨迹与角色位移，不能单纯使用“半径四格内全部命中”。横斩适合近中距离扇形攻击，突刺更长但更窄。第一版优先通过不同的真实轨迹形成距离差异，而非大量隐含伤害倍率。

## 5.3 架势稳定度

`Posture Stability ∈ [0,100]`：100 稳定，0 崩势。

| 事件 | 稳定度示例变化 |
|---|---:|
| 普通攻击被格挡 | 防守方 -8 |
| 重击被格挡 | 防守方 -20 |
| 精准格挡 | 防守方 -2 |
| 普通攻击直接命中 | 目标 -12 |
| 重击直接命中 | 目标 -22 |
| 脱离压制并经过恢复延迟 | +2/tick |

这些是平衡草案。玩家崩势通常应短于普通怪物（可先测试普通敌人约 12–20 tick）；Boss 可以采用专属规则。**崩势是追击机会，不是自动死亡判决**。普通生命伤害依然持续有效，不要求敌人先崩势才能掉血。

## 5.4 高速追击与抗无限连

```text
崩势 → 切上 → 空中轻击 → 空中返刃 → 追击斩 / SA → 落地
```

一次有效追击链分配初始 **3 点控制预算**：空中普通攻击消耗 1 点，高级追踪或再次击飞消耗更多。耗尽后目标进入短暂抗浮空保护。连招伤害衰减与目标抗控制状态不能被 SA 或 Burst 轻易重置。保护主要限制连续控制，不应禁止全部普通攻击。

# 第六部分：SA 特殊攻击系统

## 6.1 SA 的定位

**SA（Special Attack）是 Combat Style 提供的特殊能力，而不是独立于 ActionRuntime 的技能引擎。** 一把武器可默认装备一项主动 SA，统一按 V 发动；SA 可以独立释放、从连招派生、用于反击，或短时间修改动作图。

| SA 类别 | 战术意义 | 打刀示例 |
|---|---|---|
| 攻击型 | 命中、范围、追击 | 次元斩 |
| 转换型 | 改写后续连招入口 | 幻影步 |
| 形态型 | 临时改变动作规则 | 修罗架势 |

普通 SA 默认不强制消耗 Burst，避免玩家为了保留脱困资源而长期不敢使用特殊攻击。SA 可用自身冷却、出招风险或武器专属资源平衡；高阶 SA、奥义可使用独立成本。

## 6.2 SA 多上下文变体

| 当前合法上下文 | V 键结果 |
|---|---|
| 空闲 | Neutral Variant：独立 SA |
| 合法的连招取消窗口 | Combo Variant：连招 SA |
| 精准格挡后 | Counter Variant：反击 SA |
| 空中追击 | Aerial Variant：空中 SA |
| 敌人崩势且有终结窗口 | Finisher Variant：终结 SA |

同一 SpecialAbility 维护多个 `ActionVariant`，共享装备槽和身份，但具体动画、时间轴、判定、位移、取消窗口与伤害参数可不同。变体从**合法候选集**中按确定优先级选择；不可因高优先级候选失败便在非法动作中直接启动中立 SA。

## 6.3 首个 SA：次元斩

| 参数 | 独立次元斩初始值 |
|---|---:|
| 前摇 | 10 tick |
| 斩击生成 | 2 tick |
| 后摇 | 12 tick |
| 有效距离 | 约 4 格 |
| 伤害倍率 | 1.8 |
| 崩势伤害 | 25 |

连招版本可缩短前摇但降低覆盖或威力；反击版本在精准格挡后抢回先机；终结版本消耗控制预算并具有更明确的结束恢复；空中版本沿用合法的空中运动规则。挥空需要承担成本，而成功命中可开放后续攻击、重击终结或纳刀收势。

## 6.4 SA 是连招的转换器

```text
横斩 → 返刃 → SA：幻影步 → 突刺 → 上挑 → 空中追击
```

部分 SA 不直接制造大量伤害，而是在动作成功后激活临时 `ActionGraphModifier`，增加、替换或禁止若干转换边。用于修罗架势、武器附魔、双持形态、变身或其他第三方战斗风格。修改器不直接变更全局不可变动作图，而是在当前上下文中提供声明式转换候选，并统一通过 Scheduler 校验。

# 第七部分：Burst 爆气系统

## 7.1 目标与资源

Burst 是全局战术能力：帮助玩家**摆脱连续控制、延长合法进攻，或主动打破僵持**。默认使用 B 键、共享 `Burst Gauge 0–100`。

| 行为 | 获取量（原型值） |
|---|---:|
| 轻攻击真实命中 | +3 |
| 重攻击真实命中 | +5 |
| 精准格挡 | +8 |
| 成功规避有效攻击 | +5 |
| 承受有效伤害 | +3 |
| 普通格挡 | +1 |
| 攻击空气 / 原地等待 | 0 |

限制同一攻击实例、同一目标及重复交互的收益，并设置交互冷却和获取上限。不能通过安全区域反复闪避、挂机格挡或反复攻击无效目标刷槽。不建议长按按键原地充能。

## 7.2 防御 Burst（Defensive Burst）

| 属性 | 初始规格 |
|---|---|
| 消耗 | 100 |
| 触发 | 合法的受击硬直、格挡硬直或部分崩势 |
| 启动 | 1 tick |
| 防护 | 约 3 tick，覆盖必要脱困阶段 |
| 作用半径 | 约 3 格 |
| 生命伤害 | 0 |
| 效果 | 解除指定硬直、产生冲击与击退、重置近身距离 |
| 退出 | 短暂恢复，不保证立即反杀 |

爆气可以被对手提前后撤规避击退，但不应因对方已离开范围而取消本来合法的基础脱困保护。Boss 可抵抗击退，玩家仍应得到有界脱困收益。某些特殊抓取及不在允许列表中的状态不应被无条件解除。

## 7.3 进攻 Burst（Offensive Burst）

消耗 **60**，仅在动作定义明确授权的取消窗口使用。作用是取消部分后摇、开放额外派生、调整连招路线。

```text
横斩 → 返刃 → 袈裟斩 → Burst → 瞬步斩 → 次元斩
```

同一控制链最多一次进攻 Burst，不重置目标抗浮空、不重置伤害衰减、不允许无条件取消所有重击前摇。命中取消与挥空取消区别对待。**价值是更多选择，不是普遍伤害翻倍**。

## 7.4 中立 Burst（Neutral Burst）

消耗 **70**，自由行动时启动短暂“气势解放”，建议初始 **120 tick（6 秒）**。提供若干强化连招边、一次强化踏步或更强破势派生，并允许特定 SA 变体。不默认提升所有攻击伤害、扩大判定范围或提供持续无敌。

```text
普通：轻 → 轻 → 重
爆气：轻 → 轻 → 瞬步 → 重 → SA
```

气势解放需有清晰可观察前摇，对方可以抢攻、调整距离或稳守反击。鼓励主动利用窗口，不让爆气后躲避等待成为最优策略。

## 7.5 Burst 优先级与统一执行

| 当前状态 | 按 B 的含义 |
|---|---|
| 可脱困的受击状态 | 防御 Burst |
| 有合法 Burst 取消窗口 | 进攻 Burst |
| 允许自由行动 | 中立 Burst |
| 不允许 / 资源不足 | 拒绝，或仅在有效短窗口缓冲 |

优先级为 **防御脱困 > 进攻取消 > 中立解放**。`BurstResolver` 只提出合法的动作转换申请，资源扣除、状态提交、碰撞及网络广播全部经由服务端 `ActionScheduler`。第三方 Burst Profile 可自定义外观、动作和追加效果，但不能覆盖服务器验证与同步规则。

## 7.6 Burst 与 SA 的边界

- **SA**：武器／流派的特殊能力，解决“怎样攻击或改变路线”。
- **Burst**：框架战术资源，解决“何时脱困、延长或主动改写节奏”。
- **奥义**：可由 SA 和特定战斗状态组合触发的高成本终结动作。

不要仅把 Burst 实现为药水 Buff；其核心是**在严格窗口内申请特殊 ActionGraph 转换权限**。

# 第八部分：双视角相机与动画设计

## 8.1 统一规则、两套表现

| 维度 | 第一人称 | 第三人称 |
|---|---|---|
| 输入、连招、命中、资源 | 与第三人称相同 | 与第一人称相同 |
| 视觉动画 | 手部、刀具、近景轨迹 | 全身骨骼和完整持刀姿态 |
| 镜头语言 | 稳定、精准、低眩晕 | 身位、空间感、平滑跟随 |
| HUD | 准星中心的轻量提示 | 目标标记、周围空间提示 |
| 视角切换 | F5 即时替换表现资源 | F5 即时替换表现资源 |

F5 切换时按当前动作实例的绝对进度采样目标视角动画，**不重新开始动作、不再次命中、不改变服务器动作状态**。

## 8.2 四个方向量必须解耦

| 变量 | 含义 |
|---|---|
| `ViewDirection` | 玩家真正观察的方向 |
| `CombatAim` | 按准星和合法目标辅助计算的期望瞄准 |
| `AttackDirection` | 当前招式被允许使用的实际攻击方向 |
| `CameraTransform` | 最终客户端镜头位置、旋转和偏移 |

第三人称越肩模式先通过屏幕射线求候选目标点，再从玩家眼部／逻辑攻击原点求解方向并进行遮挡与角度验证。禁止利用镜头越过墙角的视线绕过服务器攻击检测。

## 8.3 第一人称相机规范

- 镜头默认固定在玩家眼部；玩家鼠标输入不被招式强制覆盖。
- 横斩是**武器在画面中横斩**，不是摄像机被强制旋转 90°。
- 攻击造成的镜头滚转、动态 FOV、额外摇晃默认关闭或极低。
- 第一人称使用专门制作的武器与手部动画，可视觉夸张但不能扩大命中范围。
- 不能用巨大的刀光持续遮挡准星和目标。
- 所有镜头反馈可关闭，并且不影响逻辑判定。

## 8.4 第三人称与高级动作相机

支持**原版第三人称**（安全兼容预设）和**动作越肩相机**（高级可选预设）。

| 参数 | 测试起点 |
|---|---:|
| 镜头后方距离 | 3.5 格 |
| 水平肩偏 | 0.45 格 |
| 跟随平滑时间常数 | 约 80ms |
| 强制自动转向 | 默认关闭 |
| 镜头滚转 | 默认关闭 |
| 墙体遮挡回缩 | 必须启用 |

期望镜头位置到角色观察锚点需要碰撞检测。遇到墙壁时缩短距离并同步减小肩部偏移；离开障碍后平滑复位。攻击方向约束由服务端动作而非相机动画决定。

## 8.5 共享 Gameplay Timeline 与独立表现

```text
ActionDefinition
├── Gameplay Timeline（服务端权威）
│   ├── 前摇 / 有效帧 / 恢复
│   ├── 位移与碰撞轨迹
│   ├── 无敌、格挡及取消窗口
│   └── 攻防结果和资源规则
├── First-Person Presentation
│   ├── 手臂 / 武器动画
│   └── 近景刀光、音效、镜头反馈
└── Third-Person Presentation
    ├── 全身骨骼与武器挂点
    └── 世界空间特效和角色运动反馈
```

服务端只加载 Gameplay 定义及必要的轻量碰撞轨迹，专用服务器不得依赖 OpenGL、玩家渲染模型或客户端资源。

## 8.6 动画制作工作流

`Blender → 统一骨骼、刀鞘与武器挂点 → 动画/碰撞轨迹导出 → 资源编译校验 → 客户端骨骼求值 → 1.7.10 渲染适配`。

资源应规定统一的坐标系、时间单位、绑定姿态、骨骼命名、插值模式和轨迹采样规则。第三人称动画可使用完整骨骼；第一人称有独立近景动画；服务端仅需要简化碰撞关键点。`ModelBiped` 可以作为第一阶段适配器，但不应成为整个动画格式。

# 第九部分：操作反馈系统

## 9.1 反馈由语义事件驱动

| 事件类别 | 可见反馈 | 音效 | 玩家感知 |
|---|---|---|---|
| LIGHT_HIT | 小刀光和受击动作 | 轻打击声 | 清脆、连续 |
| HEAVY_HIT | 强刀光和较大动作 | 重击音 | 有重量 |
| PARRY | 火花和清晰确认标记 | 特征格挡音 | 反击机会已出现 |
| GUARD_BREAK | 崩势动画和提示 | 破势音 | 可以追击 |
| MISS / WHIFF | 纯挥刀轨迹 | 破风声 | 挥空有代价 |
| SPECIAL | 独特动作与特效 | SA 专属音 | 战术高潮 |
| BURST | 释放动作与冲击波 | 爆发音 | 战斗节奏转换 |

普通命中与崩势同 Tick 发生时，由反馈系统合并优先级，避免所有镜头震动、闪光、声音机械叠加。

## 9.2 Hitstop 与服务器逻辑隔离

Hitstop 只暂停本地表现动画的某些采样，不暂停 Minecraft 服务端 Tick、输入处理、碰撞或真实计时。建议初始视觉值：轻击约 1 渲染帧、重击约 2–3 帧、精准格挡约 2 帧、崩势约 3–4 帧。**最终应按毫秒定义并设最大值**，避免高低 FPS 用户得到截然不同的反馈时间。

## 9.3 可访问性与可调节性

镜头震动、闪光、动态 FOV、粒子强度、Hitstop、伤害数字都能独立关闭或调整。关闭特效后必须仍可通过音效或 HUD 理解攻击是否命中、格挡是否成功、SA 是否就绪以及 Burst 是否发动。不能让任何战术信息只依赖刺眼光效。

# 第十一部分：命中与运动系统

## 11.1 连续刀刃扫掠

攻击判定采用若干刀刃采样点构成的扫掠体积，而非固定圆形周围范围攻击：

```text
刀柄 A ─── 刀身 B ─── 刀尖 C
    前一采样姿态 + 当前采样姿态
                    ↓
              构造扫掠体积
                    ↓
             AABB 粗筛候选
                    ↓
        Swept Segment / Capsule 窄相
                    ↓
             收集命中候选
```

服务端根据 Gameplay 轨迹计算，客户端可以使用更精细的视觉刀光，但不能上报任意刀尖位置或命中列表。同一动作实例对同一目标默认只结算规定次数。20 TPS 下高速斩击可以在一个 tick 内做轨迹子采样；这**不是**把服务器物理 Tick 提高到 60 TPS。

## 11.2 移动分类与 Root Motion

将移动拆成用户输入位移、招式 Root Motion、受击击退/浮空以及地形/物理限制。动画可定义期望位移曲线；真实世界位置通过服务端碰撞与合法移动求解，不能直接大幅 `setPosition` 穿墙突进。突进遇墙中断时，给客户端明确的动作受阻结果并校正视觉位置。

## 11.3 全局分阶段战斗 Tick

```text
1. 收集与校验全部输入
2. 处理动作转换申请
3. 推进全部动作时间轴
4. 计算合法位移与空间碰撞
5. 生成所有攻击命中候选
6. 冻结本 Tick 攻防交互所需状态
7. 统一结算命中 / 格挡 / 冲突
8. 提交生命、崩势、硬直及资源变化
9. 生成同步事件
```

同 Tick 双方攻击的结果由明确定义的优先级、防御和相持规则决定，不应取决于谁先被实体遍历循环处理。避免检测到候选命中就立刻修改对方动作，导致先 Tick 者天然占优。

# 第十二部分：服务端权威与客户端预测

## 12.1 职责与安全边界

| 行为 | 客户端 | 服务端 |
|---|---|---|
| 读取与转译按键 | 负责 | 接收意图 |
| 预测当前动作、镜头及刀光 | 负责 | 最终确认 |
| 动作是否合法、资源是否充足 | 可预测 | **权威** |
| 命中、伤害、击退、崩势 | 只能预测轻量视觉 | **权威** |
| Burst 脱困是否成功 | 视觉预测 | **权威** |
| 其他玩家动画 | 按服务器动作事件插值 | 广播事件 |

不能信任客户端发送的伤害、实际命中目标、任意刀尖坐标、动作开始 Tick 或“我刚才已经格挡成功”的断言。

## 12.2 网络消息协议（建议）

| 消息 | 方向 | 主要字段 |
|---|---|---|
| `C2SInput` | C→S | sequence、buttons/intent、moveX、moveZ |
| `S2CActionStart` | S→C | entityId、actionInstanceId、actionId、startTick、ackSeq、revision |
| `S2CActionResult` | S→C | instanceId、hit/guard/posture 结果 |
| `S2CStateSnapshot` | S→C | 状态修订、动作进度、资源、武器状态 |
| `S2CActionReject` | S→C | 输入序号、拒绝原因、权威修订 |
| `S2CBurstEvent` | S→C | Burst 类别、动作实例、确认状态 |
| `S2CCombatEffects` | S→C | 仅同步有必要的世界特效事件 |
| `S2CDefinitionManifest` | S→C | 游戏规则版本、配置哈希 |

不要每 tick 广播所有骨骼姿态。动作开始时广播动作实例及服务器时间戳，远端客户端根据动作资源采样；状态快照负责加入追踪范围、重连和纠偏。Minecraft 原生移动同步仍负责通用移动，战斗协议只负责动作意图和战斗结果。

## 12.3 预测与校正

```text
玩家按 LIGHT
  ├── 客户端立即预测横斩、起手音效
  └── 发送 C2SInput(seq=100)
              ↓
       服务端检查动作窗口和装备
              ↓
       创建权威 ActionInstance
              ↓
       广播 S2CActionStart(ack=100)
              ↓
       本地客户端对齐进度；远端客户端插值
              ↓
       命中结果由服务端另行确认
```

小幅动画时间差可平滑修正；预测动作类别错误或被服务器拒绝时，应撤销未确认的命中表现并尽快切回权威状态。非本地玩家可以测试 2–3 tick 的显示插值缓冲，但其视觉延迟不改变服务端结算时刻。

## 12.4 RTT 与精准格挡

第一版采用短输入缓冲、清晰敌人前摇和服务端权威触发，不直接实现全世界回滚。随后可为 PvP 建立有限历史记录：玩家位置、朝向、动作、防御窗口及碰撞状态；经过服务器认可的时间同步和严格回溯上限校验特定交互。不能无上限接受客户端“几 Tick 前我已格挡”的声明，也不能在历史补偿中任意撤销已经落地的所有世界副作用。

## 12.5 网络线程和输入安全

Netty 消息回调只解码、做基本包长和格式校验、再入队；对 `World`、实体、伤害、资源和坐标的实际修改在服务器逻辑线程完成。维护递增输入序号、重复/过期检测、输入频率上限、合法武器与动作验证。换刀、重生、跨维度、断线时清空不再有效的输入和预测状态。

# 第十三部分：Forge 1.7.10 渲染实现

## 13.1 可用的集成点

- **`RenderHandEvent`**：参与第一人称武器和手部表现；包含 `partialTicks`。
- **`RenderPlayerEvent.Pre/Post`**：第三人称玩家模型绘制适配及特殊动画注入。
- **`RenderWorldLastEvent`**：世界空间刀光、攻击轨迹可视化和调试盒。
- **`SimpleNetworkWrapper`**：旧版 Forge 的消息分发基础。
- **`IExtendedEntityProperties`**：旧版实体扩展数据的持久化接口之一。

重要兼容性约束：**Forge 1.7.10 没有后续版本常见的 `EntityViewRenderEvent.CameraSetup` 镜头设置事件。** 越肩相机可能需要对旧版 `EntityRenderer` 进行受控介入，因此必须设计可独立关闭的相机扩展模块及原版 F5 降级路径。

## 13.2 渲染兼容原则

- 默认不无条件替换全局玩家渲染器或核心渲染逻辑。
- 与玩家模型替换、第一人称手部渲染和其他相机模组出现冲突时，可关闭高级渲染路径。
- 两种视角都不能改变 Gameplay Timeline 或服务端真实攻击轨迹。
- 第一人称和第三人称资源独立但通过同一动作 ID 与进度同步。
- 专用服务器只加载 `combat-core`、必要数据和 Forge 服务端适配代码。

# 第十四部分：战斗 AI 设计

## 14.1 玩家与 AI 共享 ActionScheduler

```text
玩家键鼠输入 ─┐
             ├── CombatIntent → Resolver → Scheduler → Runtime
AI 决策器 ────┘
```

AI 不应绕过招式时间轴直接造成“隐藏伤害”。它与玩家共享攻击、格挡、崩势和 Burst 的合法性规则，区别是意图来源。

## 14.2 最小 AI 模型

输入：敌我距离、角度、当前动作阶段、双方架势、资源、可用动作、地形危险。使用带权重评分的有限状态决策先实现：接近、试探、进攻、格挡、闪避、追击、后撤。不要第一版就上复杂行为树或学习模型。

AI 难度应优先体现在反应延迟、动作选择质量、主动性、资源管理及失误率，而不是无限血量。禁止 AI 读取未发生的玩家未来输入。

## 14.3 两种测试对象

1. **训练人偶**：可配置血量和架势，显示碰撞轨迹、命中原因、当前动作。
2. **训练剑士**：两种轻攻击、一种重击、简单防御和闪避、距离选择、可调整反应时间。

用人偶测试系统正确性，用训练剑士测试博弈是否好玩。

# 第十五部分：框架扩展 API

## 15.1 三级扩展

| 等级 | 目标作者 | 能力 |
|---|---|---|
| Level 1 数据扩展 | 内容包作者 | 武器、招式、动作图、SA、轨迹、动画引用、Burst Profile |
| Level 2 Java API | 复杂附属作者 | 自定义条件、效果、资源、输入映射、AI 策略 |
| Level 3 子系统插件 | 高级开发者 | 新碰撞体、渲染适配、运动模型、特殊资源规则 |

第一版应稳定核心 Level 1/2 注册接口，不必立即公开任意替换底层服务器计算的危险能力。

## 15.2 API 概念草案

```java
public interface CombatStyle {
    String getId();
    ActionGraph getActionGraph();
    MovementProfile getMovementProfile();
    DefenseProfile getDefenseProfile();
    BurstProfile getBurstProfile();
}

public interface SpecialAbility {
    String getId();
    ActionDefinition resolve(CombatContext context);
}

public interface CombatInputProvider {
    InputFrame sample(CombatContext context);
}

public interface ActionCondition {
    boolean test(CombatContext context);
}

public interface ActionEffect {
    void execute(CombatContext context);
}
```

这些代码是结构意图，不是经过测试的最终编译接口。最终 API 需要区分只读上下文、服务端可提交效果、客户端纯表现回调，并明确定义注册和生命周期。

## 15.3 注册表和命名空间

```text
ActionRegistry       StyleRegistry       SpecialRegistry
BurstRegistry        ResourceRegistry    AnimationRegistry
EffectRegistry
```

示例 ID：`katana:iai_slash`、`katana:dimensional_slash`、`spear:thrust`、`greatsword:heavy_cleave`。注册完成后冻结静态定义；运行时不允许无控制地覆盖正在执行的动作。

## 15.4 客户端/服务端内容校验

将资源分为：

- **Gameplay Manifest**：动作图、碰撞轨迹、合法时间窗、资源及战斗规则；必须与服务端权威版本匹配。
- **Presentation Manifest**：动画、音效、刀光、相机预设；可以有受控的客户端视觉差异。

V1.0 连接时验证内容 ID、版本或规则哈希；暂不实现完整远程下载或战斗中热更新。

# 第十六部分：PvE、PvP 与服务器配置

## 16.1 PvE

保证原版僵尸、骷髅和其他普通怪物可以直接被战斗武器攻击。范围攻击可以命中多实体，但不应让普通怪物无限击飞。Boss 可自定义受击和崩势，防御 Burst 可提供有限的被围攻脱困收益。

## 16.2 PvP

PvP 更强调反制：连招受控时长上限、伤害衰减、目标浮空保护、Burst 脱困、防御判定公平性与服务端位移校验。先手获得合理收益，但不能“一次命中控制到死”。PvE / PvP 可使用不同倍率及控制保护，但同一个按键的基础语义应相同。

## 16.3 配置示例

```ini
# combat-server.cfg （概念示例）
[combat]
enableCombat=true
enablePvPCombat=true

[defense]
enablePosture=true
enablePerfectGuard=true

[burst]
enableBurst=true
maxBurst=100

[pvp]
enableComboProtection=true
enableLaunchProtection=true

[network]
enableLagCompensation=false

[debug]
enableCombatLogging=false
```

服务器决定规则；客户端设置只影响表现、按键和可访问性，不得调整攻击范围、资源消耗、格挡时窗或伤害。

# 第十七部分：兼容性与异常处理

## 17.1 必须定义的生命周期

死亡、重生、维度切换、下线重连、换刀、扔掉武器、打开 GUI、骑乘、传送、实体卸载、战斗中掉落物品。对每一种情况制定：动作取消、预测清理、资源持久化、追击预算重置、动画停止与服务器重新同步规则。

例如跨维度不得继承原维度的突进斩；玩家实体替换时只继承明确允许的持久数据，而不是整个 `ActionInstance`。

## 17.2 兼容优先级

优先兼容标准 Forge 伤害链、原版实体、普通装备及非渲染类内容模组。专项测试自定义玩家模型、第一人称手臂、相机、动作核心修改和实体碰撞盒。高级相机与专门渲染注入提供显式降级开关，而不能使核心战斗全部无法运行。

# 第十八部分：性能目标

20 TPS 下服务器单 tick 目标预算约 50ms。战斗系统必须在这个预算内与原有世界、实体、AI、方块 Tick 共存。

| 项目 | 目标或策略 |
|---|---|
| 服务端逻辑 | 固定 tick，明确阶段顺序 |
| 动作配置 | 启动时预编译，热路径不解析 JSON |
| 命中检测 | 只在有效窗口，AABB 粗筛后窄相 |
| 状态同步 | 事件驱动 + 按需快照 |
| 动画同步 | 不逐帧传输骨骼 |
| 内存分配 | 降低热路径短命对象和 GC 尖峰 |
| 战斗 AI | 非活跃实体不运行完整决策器 |
| 客户端特效 | 对象池、距离裁剪、可调质量 |

“20 名玩家同时战斗仍保持稳定的服务器响应”作为早期目标，但不能预先宣称已经实测达成。测试应关注最慢 Tick、99 分位 Tick、GC 停顿和大规模同时命中峰值。

# 第十九部分：开发计划与验收标准

## Milestone 1：基础操作原型

实现一把打刀、轻攻击、重攻击、格挡、踏步、纳刀、三种攻击、输入缓冲、动作窗口、服务端命中。验收：基础连招可靠、操作结果可预测、挥空与命中可分辨，服务端拒绝非法动作。

## Milestone 2：双视角与动画

完成第一人称武器、第三人称全身动作、F5 中途切换、共享动作时间轴和命中轨迹调试。验收：视角切换不重置动作、不重复伤害，两视角判定一致，正常运动不被夸张动画覆盖。高级越肩镜头可先作为实验模块，不阻塞核心战斗。

## Milestone 3：攻防与崩势

普通格挡、精准格挡、稳定度、崩势、重击破防、训练剑士。验收：持续防御不能无损永久拖延，攻击与防守都能获得合理先机，普通玩家无需连续精准格挡仍可通关。

## Milestone 4：SA

SA 注册、独立/连招/反击变体、次元斩、合法衔接。验收：一个按键稳定选择合法变体，非法请求被拒绝，挥空有成本，SA 可创造新动作路线。

## Milestone 5：Burst

0–100 资源、防御/进攻/中立爆气、反馈与服务端同步。验收：允许有限脱困、可扩展连招、可打破对峙；不能刷槽、无限取消或无限浮空。

## Milestone 6：第二武器验证框架

实现**长枪**而不是另一把打刀。覆盖另一套射程、轨迹、移动、防御、连招、SA 与 Burst Profile。若核心代码到处增加 `if (weapon == SPEAR)`，说明抽象失败，应该重构接口。

## Milestone 7：多人压测与兼容

测试 20–50 玩家混战、50/100/200ms RTT、抖动、重复/乱序输入、低 TPS、同 Tick 交互、换刀、重生、跨维度及高风险模组兼容。完整记录可重放输入与动作状态。

# 第二十部分：玩家体验验证

## 20.1 三种必测环境

**场景 A——普通生存：** 打僵尸、远程骷髅、矿洞贴墙、攻击后开箱子、切快捷栏和两视角切换。要求不牺牲 Minecraft 基础交互。

**场景 B——剑术 1v1：** 距离、精准格挡、重击破势、SA 派生、双方僵持、Burst 脱困和中立爆发。要求多种战术都有适当收益。

**场景 C——多人混战：** 多目标、范围 SA、防御 Burst、第三人称遮挡和同时命中。要求视觉清楚、服务器结算正确。

## 20.2 推荐体验指标

| 指标 | 用途 |
|---|---|
| 输入到初始动画反馈延迟 | 测量跟手程度 |
| 合法输入实际执行率 | 检查窗口和缓冲 |
| 玩家期望动作与实际动作不一致次数 | 发现上下文选择歧义 |
| SA 使用率 | 判断特殊招式是否融入基础战斗 |
| Burst 类型分布 | 检查三类 Burst 是否都有意义 |

| 预测校正次数、幅度、频率 | 评估多人同步 |
| 服务器最慢 Tick、GC | 评估工程性能 |

玩家测试应同时覆盖动作游戏熟练者和普通 Minecraft 玩家。理想结果是前者能利用细节拓展战术，后者不需要读大量手册便能稳定战斗。

# 第二十一部分：完整战斗示例

**场景：** 玩家使用打刀，面对一名具备基本攻防的剑术敌人。

1. **试探。** 玩家纳刀观察，对手横斩。玩家后撤避开，对手挥空进入恢复。
2. **夺先。** 玩家在合法间合发动居合一闪，命中后接横一文字、返刃。
3. **攻防。** 对手开始格挡；玩家切换袈裟重斩，削减对手架势，再踏步调整身位。
4. **崩势。** 后续重击使对手稳定度归零，开放切上、终结 SA 或纳刀收势三种选择。
5. **反转。** 玩家选择切上与空中追击。对手资源充足，在合法硬直中发动防御 Burst，震开玩家。
6. **反攻。** 对手转入中立 Burst 解放状态并强化踏步接近；玩家精准格挡后获得短暂反击窗口。
7. **终局。** 玩家用积攒的 60 点 Burst 发动进攻取消，连接瞬步斩与次元斩，最终纳刀。

```text
纳刀观察 → 间合后撤 → 居合命中 → 横斩 → 返刃
                                         ↓
                                     重击破势
                                         ↓
                                      崩势切上
                                         ↓
                                  对手防御 Burst
                                         ↓
                                   对手中立爆气
                                         ↓
                                     精准格挡
                                         ↓
                              进攻 Burst → 瞬步 → SA
                                         ↓
                                      纳刀收势
```

玩家实际使用的仍是少量基础按键；复杂性来自当下时机、动作窗口、距离、敌人行为和资源选择。

# 第二十二部分：V1.0 范围、风险与架构结论

## 22.1 V1.0 与后续版本的边界

| 子系统 | V1.0 | 后续扩展 |
|---|---|---|
| 普通攻击、重攻击、格挡、踏步 | 完整 | 更多方向分支 |
| 居合与打刀连招 | 完整第一套 | 其他剑术流派 |
| Posture 与受控追击 | 基础可玩 | 特殊 Boss 规则 |
| SA | 独立/连招/反击等核心能力 | 更多特殊效果与奥义 |
| Burst | 防御/进攻/中立 | 更多战斗风格差异 |
| 第一、第三人称 | 完整基础支持 | 更高级的动作相机 |
| 自定义骨骼动画 | 数据驱动基础 | 分层混合与高级 IK |
| 联机 | 服务端权威、输入预测 | 有限历史延迟补偿 |
| AI | 测试剑士与训练人偶 | 专用 Boss、复杂战术 |
| 战斗内容 | 打刀；长枪用于框架验收 | 大剑、双刀、拳术、魔法 |
| 扩展 API | 核心注册和声明式规则 | 高级插件机制 |

## 22.2 已知关键风险

1. **1.7.10 全身骨骼动画和旧版渲染兼容。** 应先验证第一/第三人称替换路径，再投入大量动画资产制作。
2. **高级越肩相机与其他核心修改模组冲突。** 必须保证可关闭、可降级，原版 F5 不受影响。
3. **20 TPS 下高速刀刃轨迹。** 需要连续扫掠和合理子采样，不能用单 Tick 静态半径判定代替。
4. **多人 RTT 与精准防御公平性。** 第一版先使规则确定和可预测，再渐进引入有限补偿。
5. **系统复杂度增长。** 打刀是第一套可玩的验证实例，长枪是判断框架抽象是否成功的第二实例。
6. **PvP 控制链过长。** 连招预算、伤害衰减、抗浮空与防御 Burst 必须协同测试。

## 22.3 最终架构

```text
                     COMBAT CONTENT
               Weapon / Style / SA / Burst
                            │
                            ▼
                       COMBAT API
                  Registry / Extension
                            │
                            ▼
                       COMBAT CORE
        ┌─────────────────────────────────────┐
        │ Input → Resolver → ActionScheduler  │
        │ ActionGraph / Timeline / State      │
        │ Movement / Collision / Defense      │
        │ Damage / Posture / SA / Burst        │
        └─────────────┬───────────────────────┘
                      │
           ┌──────────┴──────────┐
           ▼                     ▼
    FORGE 1.7.10 ADAPTER    CLIENT PRESENTATION
    Entity / World          First / Third Person
    Damage / Networking     Animation / Camera
    Tick / Lifecycle        Effects / HUD
```

### 三项冻结的技术决定

1. **统一 ActionRuntime。** 普通攻击、重击、格挡、闪避、SA、Burst 都走一套动作选择、调度、时间轴和结算。
2. **Gameplay 和 Presentation 彻底分离。** 服务端负责规则与战斗结果；客户端负责镜头、动画和特效，两种视角只是表现适配器。
3. **Combat Style 组合式扩展。** 新武器组合动作图、输入配置、资源、运动、防御与特殊能力，而不是在核心中不断写武器特判。

### 结语

Clashweave 的目标不是“特效更华丽的 SlashBlade”，而是建立一套能在 Minecraft 1.7.10 上长期复用的动作战斗基础设施。**操作简单、决策深刻、联机可信、视角自由、内容可扩展**，才是这套框架真正的产品价值。
