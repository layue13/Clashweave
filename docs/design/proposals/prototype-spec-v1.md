# 原型任务说明

> 本页已通过设计审核（2026-10-09），当前执行第 1.1 节的技术探针，尚无战斗实现。总体战斗基线已经接受；输入补位、窗口和管线选择为原型起点，数值可调，不宣称平衡或人体工学已验证。
> 优先关系：用户审核结论 → 负责模块当前规则 → 本页原型候选 → 未被修改的原稿。完整内容范围继续保留。

## 1. 目标与阶段

原型需要证明玩家可以在间合、继续进攻、压制、特殊派生、收势和防守之间作选择，并在基础交锋中体验武器/SA 表现。

| 交付 | 必须完成 | 输出 |
| --- | --- | --- |
| P0 数据和运行时 | 动作定义/实例、节点转换、缓冲、权威提交、拒绝/中断、轨迹去重；不加载客户端类的服务端路径 | 有意义的时序/失效/去重验证和可调数据 |
| P1 资产与输入接入 | 占位刀/鞘、横斩和纳刀挂载、第一/第三人称进度、F5、持刀映射/交互；最小双人同步 | 客户端导入和双人复现记录 |
| P2 完整交锋 | 原稿剑术骨架、防御/崩势/有限追击、SA 附加与主动变体、气/模式循环、普通实体适配 | 完整玩法演示、参数表、舒适度/控制时长与模式使用记录 |

P0/P1 是接通管线的阶段，不代替 P2。高级 IK、所有形态、正式美术与第二武器可后置，但仍保留总体要求；模型不兼容的降级策略需有明确说明。

### 1.1 技术探针闸门（P0 之前）

第一轮（[报告](../../probes/README.md)，代码在分支 `probe/s1-s5`）与第二轮（[报告](../../probes/round2/REPORT.md)，代码在分支 `probe/round2-independent`）探针已完成并经用户审核。下表为当前采纳的方向；标注“待验证”的 S1d、S2c 需在第 1.2 节验证，未通过前不扩大内容投入。

| 探针 | 要证明 | 第一轮结论与修订方向 |
| --- | --- | --- |
| S1 伤害与无敌帧 | 7 tick 间隔的多段命中都能结算，不被原版受击无敌吞掉 | 通过（S1d，[报告](../../probes/round3/S1d-damage.md)）。瞬时修改共享字段的方案（S1b、S1c）均失败。采用：按 (动作实例, 目标, 段号) 去重；交锋期间持久缩短目标 `maxHurtResistantTime`（20→8，等强来源的有效拒绝窗口 10→4 tick，用户已接受），命中为普通 `attackEntityFrom`，不改任何瞬时字段；进入时已有的 timer 不改，退出只在当前值仍为本模组所写时恢复 |
| S2 玩家位移 | 突进/踏步在 100ms RTT 下不回弹，穿墙被拦截 | 通过（S2c，[报告](../../probes/round3/S2c-movement.md)）。采用：玩家自身位移由客户端预测；服务端 tick 结束时按累计预算（速度 × (单调经过时间 ÷ 50ms + 2 tick 余量)，并受动作声明的总距离上限约束）对照实际位置变化，超出则 S08 拉回；动作开始用准备传送握手；墙由原版 processPlayer 逐包拦截，不自制扫掠；击退/浮空由服务端下发速度 |
| S3 双人格挡 | 精准格挡在延迟下可用 | 通过（S3b 不变量口径，360 条违例 0，[报告](../../probes/round3/S3b-invariants.md)）。采用延后提交（几何按原命中 tick 冻结）：stamp 在窗口内且在截止前到达的输入成功，之后到达的失败。延后 2 tick 的实际覆盖单程约 46.8–108.0ms，延后 3 tick 约 69.1–148.0ms，随按下相位和真实 tick 节奏变化，不保证固定物理时长；代价是伤害与防御确认延后到提交 |
| S4 占位刀渲染 | 刀/鞘挂点、一次挥刀、第一/第三人称进度可显示 | 通过（静态原版手臂适配器，S4b 有双视角截图与尺度/坐标约定）；骨架、分段躯干、轨迹对齐仍未验证；静态 OBJ + PNG，动画与挂点单独版本化数据 |
| S5 键位接管 | 持刀时屏蔽原版潜行，交锋/平时态切换不丢输入、不制造假精准格挡 | 通过（脚本场景，0/100ms 各 6 场景误判 0，最大生效 85.13ms）。移动输入包装需同时撤销 sneak 与 0.3 移动倍率；服务端每 tick 计算交锋态，变化时带修订号同步，客户端只预测本地已知触发；状态机见第 3 节 |


### 1.2 P0 入口条件与必带条件

第三轮（[报告](../../probes/round3/REPORT.md)）结果：S1d、S2c、S3b（不变量口径）均通过所测负载，满足 P0 入口条件；S4b、S5b 此前已通过。P0 经用户审核后开始，探针代码取自上述分支作参考，不直接并入主源码树。

**P0 必带条件**（来自三轮探针的未决边界，须在 P0 内实现并验证，不得省略）：

1. 命中管线：交锋目标的缩短 `maxHurtResistantTime` 需有明确归属（多个攻击者的引用计数）、死亡/换维度/下线/退出交锋的恢复，以及与其他模组改动该字段的保护；记录进入时旧 timer 的过渡行为。盔甲、药水、第三方实体覆写与真实联网生命周期在 P0 内补测。
2. 位移预算：使用单调时钟、动作开始握手与声明的总距离上限；补测灵敏度（略超速的客户端能否被检出，如 1.2 倍、1.5 倍）、纵向预算、与普通 WASD 和击退的叠加、持续低 TPS。
3. 格挡：默认延后 3 tick（可配置），并要求提交时刻同时满足“逻辑 tick ≥ 命中 tick + 延后量”与“墙钟 ≥ 冻结时刻 + 延后量 × 50ms”（双约束，防止服务端积压追赶时逻辑 tick 瞬间推进、压缩防守方的到达窗口；第三轮实测延后 3 的冻结到提交最短 16.9ms）。生产校时不得沿用探针的同机锚点：客户端用最近收到的服务端 tick 加本地经过时间打 stamp，服务端按年龄上限和窗口校验，伪造、重放、未来 stamp 均拒绝并有测试。输入到达与提交截止的线性化须经评审后进入生产。
4. 端到端反馈：命中确认延后对视听反馈的影响在 P0 内实测，不只测结算延后。
5. 占位刀/鞘的位置与形态（S4b 只验证了挂点存在与方向不反，位置与观感有问题，见[S4b 审核后补记](../../probes/round2/S4b-grip.md)）：纳刀态刀完全在鞘内，鞘贴左腰，鞘尖斜向身后下方，与身体纵轴夹角可配置（起始约 30–60°），不水平外凸；拔刀态刀柄在手内、刀身朝前、鞘留在腰间且不穿过腿；刀与鞘的宽度、厚度在两个视角下足以辨认为刀；站立、行走、跳跃、潜行无明显穿模；第一人称手与刀柄的相对位置合理，不呈“刀从手臂末端戳出”。纳刀、拔刀、挥刀中途各给第一、第三人称截图。

**P0 缩小垂直切片**：数据驱动的动作定义/实例/调度（核心逻辑不依赖 Minecraft 类，可单元测试）；light_1→light_2→light_3 与重击、防御（含精准）、纳刀/居合各至少一条可运行路线；S1d 命中管线；累计位移预算；延后提交的格挡；服务端交锋态同步；一只普通怪物与两名玩家的同步。SA、模式、切上/空中追击、第二武器仍按原计划后置，不删除。验收按第 8、8.1 节，并要求核心调度有 JUnit 测试：过期派生拒绝、同动作同目标命中次数、同 tick 结果不依赖遍历顺序。

## 2. 可重绑定的比较布局

| 输入 | 意图 | 原型规则 |
| --- | --- | --- |
| 左键按下 | LIGHT_ATTACK | 立即请求当前节点的轻击；长按不隐式改成重击 |
| 右键按下 | HEAVY_ATTACK | 请求重击或明确的重击派生，保持独立重击入口 |
| 左 Shift 按下/保持/松开 | GUARD_PRESS / HOLD / RELEASE | 精准时机依真实按下；不提前缓冲、不反复自动刷新 |
| 左 Alt 按下＋方向 | DODGE | 请求一次踏步，保持不自动重复；不要求同时按空格 |
| 中键按下 | TARGET_LOCK | 锁定/解除，不保证命中、不自动选择技能 |
| R 按下 | SHEATHE | 纳刀仅在空闲或声明的收势窗口执行 |
| B 按下 | MODE_ACTIVATE | 固定模式入口，资格不足或窗口不合法则拒绝 |
| V 按下 | SPECIAL_ATTACK | 临时通用主动入口；变体由当前明示节点定义，不为每项 SA 分配一个键 |

V 沿用原稿作比较键位，而非最终人体工学结论；高频连招/反击效果优先在可理解的基础衔接中表达。R/V 与移动争用手指、B 的距离、小指和拇指负担需记录，不能因为侧键绑定更舒服就要求额外鼠标硬件。原稿右键防御/F 重击布局保留为独立对照预设，不同时启用冲突绑定。

多个 SA/变体是数据能力。首个内容样例可使用次元类能力，同时为第二种机制不同的能力保留验证入口；样例能力数不是框架槽位上限。同一节点若确实有多个需要主动区分的分支，必须定义输入或明确装配选择，不暗藏优先级猜测。

## 3. 持刀与原版交互

持有启用 Combat Style 的武器时尽量接管键位：左键、右键、Shift、Alt、中键、R、B、V 表达战斗意图，Shift 不再触发原版潜行。WASD、跳跃、冲刺、快捷栏、背包、聊天、GUI 和 F5 始终放行，Q 默认仍为丢物，不把旧 Q 派生候选叠加进此预设。纳刀态与未锁敌同样适用。

**持刀时左键始终是攻击，右键始终是重击入口，对任何实体（包括村民、动物、友好生物）都是出刀，不放行挖掘和实体交互**（用户决定：刀也要用于击打这些目标，后续 Boss 等也需要）。需要挖掘、交易、喂养时切换到其他物品。是否保护友好实体（宠物、村民、同队玩家）免受误击，由服务端配置决定，默认值待定。

按游戏状态（不看准星）分两态，不设专用的临时交互键：

| 状态 | 进入条件 | 键位行为 |
| --- | --- | --- |
| 交锋态 | 锁敌；正在执行动作或防御；刚受击；有敌对目标在 `engageRadius` 内且以玩家为目标 | 完整战斗映射，不放行任何原版用途 |
| 平时态 | 离开交锋态超过 `disengageTicks` | Shift 恢复原版潜行；准星指向可交互方块（箱子、门、机器）时右键走原版交互；其余仍是战斗映射；左键与对实体的右键仍是攻击 |

其余原版操作靠切换物品恢复，不另设临时交互键。若实测发现交锋态误判过多，可再评估默认不绑定的“强制原版”可选键，不进入默认设计。

`engageRadius` 起始约 8 格、`disengageTicks` 起始约 60 tick（3 秒），均为可调测试值。退出交锋态使用迟滞，避免边缘来回切换；当前状态需有可辨识提示。判断依据只用玩家状态、锁敌和敌对目标，不用准星指向的环境，避免打斗中准星扫过箱子而改变键义。

状态切换时释放旧映射的持续输入，回到战斗后不凭已保持的 Shift 制造一次新的精准格挡，需要新的真实按下事件。动作处于承诺或恢复时不切换键义。GUI 暂停输入接管并清理缓冲，关闭后回到原状态；切物品、死亡、维度变化或断线重置为按当前状态重新判定。切物品和 GUI 不清空权威恢复、目标保护或已提交成本。

屏蔽潜行需要替换或包装玩家的客户端移动输入（初步判断，未验证；1.7.10 无对应事件），列入探针 S5。若误判率或舒适度测试不成立，可调整进入条件，稳定战斗映射的原则保留。

## 5. 节点与交锋结果

| 节点 | 明确入口/后续 | 结果限制 |
| --- | --- | --- |
| 纳刀空闲 | 轻→居合；合法防御/踏步/主动特殊 | 首个样例未声明纳刀重击，重请求拒绝并提示；不隐式先出轻击再重击，后续风格可增加明示入口 |
| 拔刀空闲 | 轻→横斩；重→袈裟；R→纳刀；V→独立变体 | 各自是单独请求，不能失败后偷换招 |
| 居合/横斩衔接 | 轻→后续轻击；重→声明的压制边；R→合法收势；V→指定连招变体 | 在命中取消窗口执行；格挡/挥空权限独立声明 |
| 返刃的合法崩势窗口 | 轻→地面继续；重→切上；R→收势；V→已明示的特殊变体 | 重请求不满足切上条件则拒绝并反馈，不自动改成高成本终结 |
| 精准格挡后的反击窗口 | 轻→普通反击；V→反击变体；合法踏步/收势 | 不直接把对方崩势；过期反击请求不变中立 SA |
| 空中追击 | 轻→有限追击；声明的重击→落斩收束；V→空中变体 | 有控制预算；不能因爆气或 SA 重新无限浮空 |
| 明示终结节点 | 声明的终结动作/SA 或合法退出 | 不因低血量自动选择；不保证击杀、不强制演出 |

横斩命中取消先采用原稿 `[7,11)` 测试窗口；其它动作需在第一版数据中列出各边窗口与结果前提。缺少显式边时先完成恢复再回空闲，不给予全程自由取消。原型执行者可以调整测试窗口，但要提交参数和原因。

轻/重/SA/纳刀缓冲先沿用原稿 4 tick，踏步与模式 2 tick；每类只保留最近有效请求，禁止无限队列。解析时锁定动作边/变体身份，执行时再验证；过期、被打断、目标或条件变化后拒绝，资源只在合法提交时结算。不得通过失效后的自动回退消费另一能力。

## 6. 攻防、资源与模式

同 tick 原型默认采用冻结交锋状态后的独立合法性判断：双方有效攻击若都满足命中且未被合法防御/保护阻止，可以交换命中，伤害/硬直随后统一提交。不因先结算一方就撤销已经合法收集的另一方攻击。相持或招式优先级作为后续明确规则扩展，不用实体遍历顺序代替。

普通/精准格挡、架势恢复、控制预算按原稿基线起步；框架允许实体采用不同防御与受控能力。普通怪物接受正常伤害，不能因为没有架势就无法战斗；不能浮空的目标使用内容声明的压制/受击结果，不自动换成另一技能。

普通踏步与攻击位移分开。回避防护起止、恢复、连续使用限制必须列入数据，不能用全程无敌或任意 `setPosition` 穿墙代替。所有移动都经过世界碰撞求解。

模式原型使用一槽，攻击/有效格挡/实际受伤参与收益，精准格挡和连贯奖励按事件限频；附加多段不能重复刷完整气。先保留已积攒资源、不做脱战衰减；死亡/重生的持久化策略和具体权重在原型配置中明示，不能含糊沿用旧三类 Burst。

满槽合法激活后消费资格，模式内暂停下一次资格积攒，结束回常态。次元样例可加入延迟空间斩和有落点/间隔/恢复限制的踏步闪移；强化不清目标保护、不自动脱困、不把普通 SA 全部锁在模式里。模式时长、气权重和强度在 P2 首次交付时提供配置与测量，不强行把旧六秒当作默认。

## 7. 最小资源与身体动画契约

Blender 是推荐源工具。先用静态刀/鞘 OBJ＋PNG 验证加载和握点，再建立版本化挂点/动画与独立权威轨迹数据；OBJ 不携带骨骼动画。资源单位、坐标转换、固定绑定姿态和时间基准必须在首个样例中明示。

刀刚性挂手、鞘挂腰。身体扭转使用骨盆→腰/胸→肩臂层级，分段网格或蒙皮与骨架一致；原版单块躯干适配器只能证明整体上身转动，不能代替正式胸腰分段表现。先验证简单部位遮罩和过渡，再扩展高级混合/IK。

客户端根据动作实例/进度播放两视角表现，服务端只读取 Gameplay 数据。模型变化和 F5 不重启动作、不重复命中。刀的可见路径与权威轨迹要对齐；头部/相机观察修正不任意扭转已承诺攻击。皮肤、盔甲和其它玩家模型适配见[资源模块](../modules/assets.md)。

## 8. 交付验收与报告

必须报告构建检查、实际运行过的客户端/专用服务端场景、资源导入方式与存在的降级。骨架 `build` 成功不等于玩家能战斗。

关键验证包括：过期派生不偷换招或扣费；同动作同目标按声明次数命中；同 tick 结果不依赖实体遍历先后；无气仍可行动；SA/模式不重置控制保护；碰墙位移不穿越；F5/GUI/换物品不刷命中或清恢复；原版交互无双重请求。

玩法报告至少覆盖：左右环绕中轻转重/主动 SA/纳刀，后退格挡与回避，跳跃后踏步，持刀潜行开箱，双视角切换，普通怪物和剑士交锋。记录误操作/停止移动、控制时长、气获取和模式机会，不只提交特效视频。

设计审核已通过；探针 S1–S5 全部有结论并经用户审核前，不进入 P0。委派时可将运行时/结算与资产/渲染分别分工，但须先共享动作身份、时间基准和资源契约，并由一个集成任务验证完整路线。

## 9. P0 审核与试玩后的补充验收

来自对 P0（PR #12）的审核和真人试玩反馈，P0 合并前须处理，后续阶段沿用。

1. **位置修正包不得引起视角变化**：任何位置修正包（含动作开始握手、预算纠正），凡导致客户端视角变化都计入“预测纠正”。连续转动鼠标时，0ms 与 100ms 各 20 条连击序列，每次动作开始前后客户端 yaw/pitch 的变化应为 0（浮点误差内），合法序列中的位置修正包应为 0。动作开始握手不使用位置传送，改用自定义消息确认预算起点；必须保留的真实纠正在客户端恢复自己的视角。1.7.10 位置包是否带相对旋转标志须对照反编译源码核实（我记忆中没有）。
2. **锁敌由服务端锥形选取**：客户端只发锁定意图，准星实体仅作提示并由服务端校验；服务端在视线前方锥形范围内（起始半角约 30°）按角度与距离打分选目标，要求视线可见，排除受保护的友好实体。获取距离与保持距离分开（起始约 16 / 20 格，保持大于获取作迟滞），均可配置；`engageRadius` 只管敌对目标瞄准判定，不与锁定距离混用。
3. **延后提交只用于可能防御的目标**：延后提交（冻结命中后等待防御输入）只对玩家目标（对方可能有防御输入）生效；对普通怪物同 tick 提交，避免 PvE 命中反馈被无谓延后约 150ms。
4. **攻击朝向取按下时的客户端视角**：输入携带按下时的 yaw/pitch 快照，服务端按最近位置/朝向包历史与最大转速校验后用于动作朝向，不再使用动作开始时服务端已知的（落后的）旋转。验收：100ms RTT 下挥刀方向与按下时准星方向的偏差。
5. **命中扫掠覆盖矮目标与高度差**：不得只沿单一水平线扫掠（P0 的扫掠线在玩家脚上 1.05 格处，矮目标如蜘蛛、幼体可能打不到，楼梯与跳跃高度差也受影响）。需覆盖不同高度的目标，并对蜘蛛、幼体、楼梯、跳跃后出刀给出实测。
6. **攻击者本地的非权威命中反馈**：权威确认延后到提交，但攻击者客户端应有不改变伤害的本地即时反馈（挥刀声、拖尾），首个反馈延迟作为指标记录。
