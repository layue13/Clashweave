# 攻击流、SA 与少量输入的统一设计

日期：2026-10-08。状态：对操作提案的修正与进一步设计，尚未实现或验证。用户指出 SA 应融入操作，不能简化成单一独立技能，并重申项目是独立框架。

关联：[输入](../modules/input.md)、[动作](../modules/actions.md)、[SA](../modules/sa.md)、[Burst](../modules/burst.md)、[交互 V2](interaction-v2.md)。

## 1. 修正此前遗漏

V1.0 已提出动作图、条件转换、SA 多上下文变体，以及 SA 作为连招入口、转换与终结节点。上一轮交互提案仅安排“基础攻击 + 一项 SA”，未充分定义这些节点如何由少量输入到达；这是文档衔接缺口，不是已完成的整合。

保留减少操作负担的目标，但不因此删掉攻击流。当前仓库也没有对应代码实现，“接入”在本阶段指设计闭环。

Clashweave 是独立动作框架，SlashBlade 是参考之一。其左右键习惯、单刀 SA 槽、评价公式与 ProudSoul 不构成本项目约束。

## 2. 三个需要分开的概念

| 概念 | 职责 |
| --- | --- |
| 输入意图 | 玩家表达继续进攻、改变路线、防守、回避等选择 |
| 动作图 | 定义当前动作在合法窗口可进入哪些后续动作 |
| SA 能力定义 | 提供有特殊效果或规则的动作、变体和转换；参与同一动作图 |

物理键不必对应具体技能，也不应让玩家不知道按下会发生什么。一个风格可以提供多个特殊能力，每个能力又可以有多个变体；不再假设所有风格都只有一项 SA。具体装配、数量与学习方式待定。

SA 可以有独立入口，也可以作为基础操作的明确派生；不要求每个 SA 一个专用键，不要求所有 SA 都只能由同一个“施放技能”键发动。

## 3. 少量输入如何表达选择

建议先用两个进攻语义评估动作图：

- 继续：沿当前清楚的基础路线衔接。
- 派生：选择当前动作明确提供的战术分支，例如破防、接近、反击或特殊转换。

这些是候选语义，尚未决定分配给左右键、键盘键还是其他输入形式。右键防御的候选方案也需要结合它们比较，不能先固定键位再强行塞入动作。

同一节点不靠一个模糊的派生输入猜测玩家想用哪项 SA。建议初版每个可读上下文只提供一条默认继续边和一条明确派生边，防御/回避作为独立合法退出；这是控制局部复杂度的原型策略，不限制框架永远只有两条边。

如果同时需要破防与追击两个独立选择，必须增加可辨识的分支入口，或重新组织节点。方向、长按和时机差异都可以评估，但不能为了省键隐性增加手势负担。

## 4. 示例攻击流

以下名称只描述战术作用，具体招式、时间窗、成本和输入映射均待定。

```text
起手攻击
  ├─ 继续 → 第二段斩击
  │           ├─ 继续 → 常规收束
  │           └─ 派生 → SA：位移转换 → 追击动作
  └─ 派生 → 压制动作
              ├─ 继续 → 常规收束
              └─ 派生 → SA：终结攻击 → 恢复

精准格挡成功 → 短反击窗口
  ├─ 继续 → 普通反击
  └─ 派生 → SA：特殊反击 → 恢复或合法衔接
```

这张图保留多个 SA、普通收束与反击选择。节点的战术含义先确定，按键如何到达再决定。它没有假定玩家必须先触发爆气才能使用 SA，也没有要求连到固定第几段才允许所有特殊能力。

对应的能力还可以声明独立入口，但不是所有能力都必须支持所有场景。独立入口、连招变体和反击变体的风险与效果需要分别定义。

## 5. 上下文不能吞掉玩家意图

当前动作、地面/空中、确认命中、反击机会和模式可以参与合法性判断。距离与锁定目标主要用于瞄准与是否可执行，不能暗中决定玩家按派生时究竟破防、位移还是消费高成本终结。

建议玩家输入时确定请求的转换边或变体身份。服务端执行时再次验证；若窗口、目标或资源失效，拒绝该请求，或只采用预先说明的安全回退，不能自动变成另一种技能并消费其成本。

锁敌不会替玩家选择连招。命中与挥空可拥有不同转换窗口，但应可通过动作和反馈理解。重要 SA 的可用分支需要清楚的教学与反馈，不能只靠背隐藏的优先级表。

## 6. 爆气的关系

基础模式已经有完整的普通动作和 SA 路线。爆气辅助进入另一模式，该模式可以有限修改现有转换边、窗口或能力变体，但不另建技能执行系统。

模式变化应保持核心输入意图，例如“继续”仍继续攻击，“派生”仍选择当前可理解的路线。模式不能不经提示把低成本动作变成高成本技能，也不重置控制预算和合法性约束。具体改变哪条路线仍待讨论。

## 7. 架构中的设计闭环

```text
物理输入 → 输入意图
               ↓
当前动作 + 已确认交锋结果 + 风格 + 模式
               ↓
动作图候选（普通动作与 SA 动作共同参与）
               ↓
确定请求 → Scheduler 校验 → ActionRuntime 执行
```

SA 的多种入口最终进入相同的调度、时间轴、命中、资源和网络机制。特殊能力不是绕开普通动作规则的执行器。

## 8. 下一步

先完成一张覆盖起手、继续、压制、反击、特殊转换、收束与防御/回避退出的最小可玩动作图，并标出每条边需要哪一种可辨识输入。

随后对比两种控制布局：保留左右键攻击/防御并增加一个通用派生输入，或将左右键作为两种进攻输入并为防御安排独立输入。需要检验紧急防御、移动时操作、第一人称使用和原版交互；本轮不直接冻结任一种布局。

简化的是需要记忆与同时操作的输入，攻击选择和风格差异仍需由完整攻击流承载。
