# Burst：辅助战斗与模式切换

> 更新：2026-10-08。状态：定位按用户反馈调整；积攒、消耗、持续时间和具体模式效果仍为提案，尚未实现或验证。
> 关联：[SA](../modules/sa.md)、[动作](../modules/actions.md)、[防御](../modules/defense.md)、[输入](../modules/input.md)、[网络](../modules/network.md)。历史问题见[机制审查](../reviews/burst-review.md)。

## 1. 当前方向与职责

用户明确提出：爆气应当只是辅助作用，或者作为切换模式的入口，不能与 SA 冲突；旧积攒方式也存在问题。随后补充：格挡与受伤也应参与积攒。

据此，后续设计以以下分工展开：

| 系统 | 职责 |
| --- | --- |
| 基础动作 | 不依赖爆气即可完成攻击、防御、移动和基本连招 |
| SA | 武器或风格的具体特殊能力，承担出招、追击、反击等内容 |
| Burst | 辅助基础交锋，提供进入某种战斗模式的机会 |
| 模式 | 声明一组有边界的规则变化；普通动作与 SA 在该规则下执行 |

爆气激活不是另一个特殊攻击按钮。模式可以提供可预测的 SA 变体，但正常 SA 应在未爆气时完整可用。模式效果由 Combat Style 配置，不要求所有武器都具备爆气模式。

“作为模式入口”不自动意味着大幅伤害加成、持续无敌或另一个技能列表。模式的价值应表现为风格上的选择，并保留代价与应对空间。

## 2. 积攒提案：有效交锋形成战斗势能

积攒来源包含有效攻击、格挡与受伤；这是按用户反馈调整的方向。建议让连续有效攻击体现主动交锋的收益，格挡与受伤提供受压方的积攒机会，具体收益比例尚待确认。这里的连续指一段交锋中的动作衔接，不要求把目标一直控制到结束，也不按鼠标点击数累计。

| 情况 | 建议处理，待验证 |
| --- | --- |
| 普通动作实际命中有效目标 | 获得基础积攒 |
| 合法连招中的后续有效命中 | 维持交锋节奏，可有限提高收益 |
| SA 多段攻击或范围攻击 | 同样遵守动作实例收益上限，避免一次技能填满 |
| 同招高频重复 | 收益递减；正常短连招仍应有基础收益 |
| 挥空、攻击无效目标、原地等待 | 不积攒 |
| 普通格挡成功承接有效攻击 | 获得积攒，按实际攻防事件结算，按住防御本身不产生收益 |
| 精准格挡 | 参与积攒，是否高于普通格挡尚待确认 |
| 承受有效伤害 | 获得积攒，数值关系与可用频率待验证 |
| 有效闪避 | 是否直接加资源或仅维持交锋节奏，尚待决定 |
| 短暂后撤、防御、切换目标 | 不立即清空既有积攒；连贯性如何保留待定 |

建议同一攻防事件按结果结算：精准格挡替代普通格挡收益；格挡漏伤如何处理需定义，不能默认把普通格挡与受伤的完整收益相加。多段攻击、持续伤害和多人围攻需有收益节流，避免只按受击包数堆积。自伤、环境伤害和无效目标是否计入需明确；优先验证仅有效敌对交锋产生收益的版本。

受伤积攒并不等于鼓励主动挨打。需要验证其模式收益不足以抵消生命损失，并让受压方有合理使用机会；模式本身不是自动脱困，基础控制保护仍独立成立。

连续攻击奖励不能鼓励无限浮空，目标抗控制与追击预算继续由防御模块维护。评价收益与角色伤害倍率分开，避免把优势直接放大为滚雪球。

攻击、格挡、受伤是当前来源方向，表中的收益方式与限制是替代方案，尚未确认。还需比较慢速武器与快速武器：按攻击次数统一给点数会偏向快武器；按动作承诺、有效交锋时间或风格收益上限归一化值得测试。

## 3. 区分短期节奏与模式使用资格

建议在逻辑上区分两个概念，界面不一定需要显示两条槽：

- 交锋节奏：描述近期有效动作的连续性，可影响积攒收益。
- 模式使用资格：已通过战斗获得的切换机会，不应因必要后撤或短暂防守立即丢失。

两者是否合并为一个数值、资格是否能跨战斗保留、受伤是否仅打断节奏，均待讨论。不要同时强制“必须连续进攻积攒”与“停止进攻立刻清空”，否则会惩罚正常的距离和防御决策。

## 4. 激活与退出的候选流程

```text
基础战斗 → 有效交锋积攒 → 获得模式切换资格
                                ↓ 主动输入，合法窗口
                           激活指定模式
                                ↓
                        普通动作 + 现有 SA
                                ↓
                         结束或主动退出
```

B 的候选语义固定为请求激活模式，V 保持请求 SA。不根据受击/攻击状态把同一个激活请求自动替换成脱困或连招取消。模式内再次按 B 的含义、动作中是否允许切换、退出方式和消费时点都需要明确定义。

为了避免模式自我供能，优先验证模式中不能再次积攒切换资格的版本；这也是提案。资源扣除、模式进入与规则修改须由统一 Scheduler 原子提交，预测失败时恢复权威状态。

## 5. 与 SA 及形态能力的关系

SA 决定使用什么能力；模式决定该能力在什么规则下执行。例：平时的次元斩已经完整可用，模式期间可在明确窗口衔接另一基础动作；SA 的身份、输入和基本用途不变。

历史稿中的“形态型 SA”需要同步审查：如果它与 Burst 都控制同一模式，必须确定一个进入入口，避免两个重复激活系统。独立于爆气的武器变形可以作为另一种能力，但须定义可否叠加与退出规则。

现阶段不继续沿用三类爆气、100/60/70 消耗及自动按状态选类作为当前设计。防御脱困需求交回防御模块评估，不能把玩家的基本行动机会绑定到攻击积攒资源上。

## 6. 待确认与验收

下一步先决定模式带来哪一种有意义的规则变化，再倒推积攒与使用频率。尚待确认：有效命中收益、重复衰减、跨目标策略、积攒保留、模式持续/退出、模式期间 SA 的合法变化。

验收应覆盖：没有爆气仍能稳定战斗；SA 不依赖爆气；慢武器不会明显吃亏；必要防御不清空全部进度；玩家不靠刷多段/无效目标续模式；新模式不会延长目标受控上限。

## 7. SlashBlade 1.7.10 参考核实

检查官方仓库 `1.7` 分支提交 `83429584fc2ee437cb48c2d31d23f353cb72bd84`，其构建版本为 `mc1.7.10-r87`：

- [StylishRankManager](https://github.com/flammpfeil/SlashBlade/blob/83429584fc2ee437cb48c2d31d23f353cb72bd84/src/main/java/mods/flammpfeil/slashblade/ability/StylishRankManager.java)：不同攻击类别有不同评价收益；部分类型短期重复会减少收益；评价有时间衰减，受伤事件通常扣评价。它还登记精准格挡等行为，不能概括为只有连续攻击。
- [ItemSlashBlade](https://github.com/flammpfeil/SlashBlade/blob/83429584fc2ee437cb48c2d31d23f353cb72bd84/src/main/java/mods/flammpfeil/slashblade/ItemSlashBlade.java) 和 [SlashDimension](https://github.com/flammpfeil/SlashBlade/blob/83429584fc2ee437cb48c2d31d23f353cb72bd84/src/main/java/mods/flammpfeil/slashblade/specialattack/SlashDimension.java)：ProudSoul 是独立的武器数据，存在增长和 SA 消费路径，与风格评价分开。
- [官方 r79 发布说明](https://www.curseforge.com/minecraft/mc-mods/slashblade/files/2299338)记录 r78 按评价是否达到 S 区分地面连招路线，说明评价可以影响动作路线。

可借鉴的是战斗表现与动作选择的联系，不能把评价等级直接当成原版爆气槽。这里未声称 SlashBlade 有与本提案相同的爆气模式。
