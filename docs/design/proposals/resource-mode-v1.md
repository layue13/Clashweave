# 气、爆气模式与攻击流：推荐原型

> 后续讨论：用户提出 SA 可以特化/改变整个攻击流程，并在爆气后转换武器或使用者形态，例如踏步变瞬移。因此本文“一两条边、少量模式变化”只能作曾提出的原型范围，不能约束能力设计；以[SA 模块](../modules/sa.md)与[Burst 模块](../modules/burst.md)的当前方向为准。常态 SA 与形态专属动作应分别定义。

日期：2026-10-08。状态：助手推荐方案，尚未经用户确认、实现或测试。相关模块：[Burst](../modules/burst.md)、[SA](../modules/sa.md)、[动作](../modules/actions.md)、[防御](../modules/defense.md)、[输入](../modules/input.md)。

## 1. 从需要解决的问题出发

基础攻击流承担持续交锋；SA 承担特殊战术选择；气来自交锋，为玩家提供偶尔进入另一种战斗模式的机会。资源管理应增加一个容易理解的决定，而不是迫使玩家同时记住三类爆气、多个独立槽与每项能力的付费规则。

推荐第一轮原型只实现一条气槽、一个主要消费入口和一套有限模式变化。它不复刻《死神 VS 火影》或 SlashBlade 的公式。分格数量、数值与持续时间不是现在的前提。

## 2. 系统分工

| 系统 | 在原型中的职责 |
| --- | --- |
| 基础动作 | 无气时即可完成进攻、防御、移动与收束 |
| SA | 多能力、多入口融入动作图，不统一要求气槽付费 |
| 气 | 攻击、格挡与受伤产生的战斗资源 |
| 爆气输入 | 在合法窗口主动请求进入模式，不另附一发攻击 |
| 模式 | 有限改变原有攻击流的连接方式，不增加一套技能键 |

SA 是否需要独立成本由具体能力的风险和强度决定，先用时间、恢复与机会成本验证，不先新增另一个通用资源槽。未来若确需高成本奥义，再单独讨论共享气消费与模式之间的取舍；本轮原型不同时引入。

## 3. 积攒：攻防双方都有机会

建议按有效交锋事件结算，而非原始按键、命中包数量或固定每刀收益。

| 来源 | 初步收益逻辑 |
| --- | --- |
| 有效攻击 | 基础收益；慢动作和快动作应在合理交锋时长内有接近的获取机会 |
| 连续有效衔接 | 小幅、有上限的连贯奖励，不让高连击者加速无限续模式 |
| 普通格挡 | 收益存在，低于同次普通受击收益是待测试的起点；按住本身无收益 |
| 精准格挡 | 单独的高质量交锋收益，优先比较与普通命中相当的版本 |
| 有效受伤 | 受压方也获得资源；基于实际损失并设窗口上限，不奖励自伤或刷环境伤害 |

这些收益不是通用线性排名，具体数值需依据模式价值与使用频率测试。防御损失生命更少，可以换取更低普通格挡收益；精准操作可获得额外回报，但不能让反复点防御成为刷气方式。

一次事件产生一种清楚的收益分类：精准格挡不再叠普通格挡完整收益。格挡漏伤可按阻挡部分和实际伤害部分拆分，但总收益必须受同一事件上限约束。多段、范围、多人围攻、持续伤害各有去重与节流，不能仅靠数量优势瞬间填满。

连贯奖励允许正常防御和短暂调整距离，不要求持续压制同一目标。中断衔接只取消未来连贯加成，不清空已积攒的气。

## 4. 保留与使用机会

推荐交锋中不随时间扣已积攒的气，不奖励原地等待。长时间脱离有效交锋后，可经宽限缓慢衰减；它只控制跨战斗囤积，不能逼玩家无脑进攻。出入遭遇、维度变化与服务器规则的保留边界仍需定义。

避免把模式当成单局只见一次的大招。目标是典型持续交锋中有机会积攒并决定是否进入模式；攻击方和受压方的可用时间都要测量，不能只测高手。

建议先以达到一个明确阈值获得一次激活资格，进入时一次性消费对应气。是否允许提前部分消费、多次储备和分格显示，等第一次模式循环验证后再决定。

## 5. 模式具体怎样辅助攻击流

首个原型建议是“已有动作之间获得少量新的衔接机会”，而非全局伤害或移速提升。

```text
基础路线：
攻击 → SA 转换 → 追击 → 收束

模式路线（候选）：
攻击 → SA 转换 → 追击
                       ├─ 收束
                       └─ 有限重整 → 已有起手或回避退出
```

重整入口可以帮助追击或重新组织位置，仍须有明确承诺与退出成本。只在指定命中/转换窗口增加合法边，不让任何动作任意取消，也不改变目标抗控制预算。同一控制链的收益受限；新的路线不意味着更长的必定受控链。

先选一到两条对战术选择确有价值的模式转换，不重做所有动作。普通输入与 SA 入口保持其可理解职责，模式状态有明显提示；不能在同一个含糊上下文突然消费另一技能的成本。

模式自身不发动 SA，进入也不附带大范围伤害或默认脱困。激活阶段必须有合法窗口和可被对手理解的反馈，不在任意受击硬直中无条件执行。

## 6. 防止模式压倒基础战斗

原型建议模式有有限持续或有限使用机会，具体退出条件待定；期间暂停获取下一次模式资格，不能靠模式攻击给自己续期。退出保留正常恢复与控制保护，不造成额外强制长硬直。

没有模式时也要能逼近、应对格挡、反击与退出。若只有模式期间才能破解基础防御，说明基础攻击流未闭合，应回到动作/防御模块修正。

## 7. 脱困另行设计

基础控制保护无资源也应成立。提前脱困若后来证明有独立价值，再比较其成本与输入。不要先给爆气键绑定受击脱困、攻击取消、中立强化三个自动含义。

受伤能积攒模式资源，并不代表该资源必须能立即解除当下硬直。需要在重新获得行动机会时有合法激活窗口，验证受压方能够实际使用。

## 8. 逐事件场景

玩家通过普通连招与 SA 路线获得气；遭到对方压制，格挡与受伤继续提供积攒。玩家在基础防御/回避规则下重新获得行动机会，选择普通反击或在合法窗口进入模式。模式使既有追击后多一个有界重整选择，对方仍能通过距离、防御或反击应对。模式结束，玩家回到完整的基础动作流。

这个过程需要验证，不能仅凭文字宣称收益平衡。它明确区分了资源获取、模式激活、特殊能力和脱困。

## 9. 最小验证范围

一套风格、一条基础动作图、至少两种特殊能力或用途清楚的特殊节点、一种模式和一条气槽。具体招式与能力数量是原型建议，不是框架限制。

比较无模式与有模式的完整交锋：检查每次投入是否增加可理解选择、无气时是否仍完整、慢/快动作收益、格挡和受伤使用机会、囤气倾向、模式期间追击控制时长，以及输入是否增加负担。

先用同一动作图验证模式的有限连接变化，再确定获得频率、阈值、时长、分格与最终按键。若模式没有独立价值，应缩减或移除其效果，不能靠大量数值加成弥补。
