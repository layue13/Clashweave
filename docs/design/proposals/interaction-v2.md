# 从玩家决策推导战斗交互

日期：2026-10-08。状态：重新设计提案，未实现或验证。用户明确允许锁敌，指出现有按键过多，要求从第一性原理出发设计。具体键位、锁定相机与输入复用尚未确认。

关联：[输入](../modules/input.md)、[视角](../modules/presentation.md)、[动作](../modules/actions.md)、[SA](../modules/sa.md)、[Burst](../modules/burst.md)。本提案优先于这些模块中的历史键位建议用于后续讨论，但不是已确认规范。

> 后续修正：本页对 SA 的独立按键描述不完整，必须结合[攻击流 V2](attack-flow-v2.md)阅读。SA 有多个能力与操作入口，旧“基础攻击 + 一项 SA”不再作为原型范围限制；键位布局需要在完整动作图基础上复核。

> 内容恢复说明：后续用户要求保留首套剑术的轻重击、切上挑飞与纳刀/拔刀状态，见[日本刀模块](../modules/katana.md)。本文中暂缓重击和自动收势的建议不能解释为删除这些战术动作；具体输入待重新映射。

## 1. 首先确定玩家必须表达的意图

战斗的基本问题是：攻击谁、保持什么距离、何时出手、何时防守，以及什么时候投入特殊能力。招式数量不是按键数量的依据。

| 玩家决策 | 表达渠道 | 初步边界 |
| --- | --- | --- |
| 看哪里、注意谁 | 鼠标移动 | 保留观察控制权 |
| 攻击谁 | 自由瞄准或锁敌 | 锁敌负责持续目标选择 |
| 在哪里交锋 | WASD | 距离、环绕、退让与接近 |
| 何时攻击 | 主攻击输入 | 基础招式衔接无需逐招绑定 |
| 何时防守 | 独立防御输入 | 不能等待长按分类才开始防御 |
| 如何脱离攻击 | 回避输入 | 允许与方向输入同时操作 |
| 选择特殊路线 | 动作图中明确的派生或独立入口 | SA 融入操作，不要求逐技能专用键 |
| 进入模式 | 模式输入 | 低频且稳定，不在受击时变成另一技能 |

初版不把手动纳刀、每一种派生、切换爆气类别都做成独立必按键。重攻击是否需要独立输入，要先证明它表达了基础攻击无法提供的重要决策。

## 2. 操作负担包括同时操作与时机

不能只把六个按键变成六种组合键就宣称简化。评估应包括：手指能否保持移动、是否需要同时按修饰键、是否等待长按识别、是否要求快速双击，以及默认鼠标是否只有两键加滚轮。

高频输入优先放在左右鼠标键；紧急输入不与慢速手势共用；模式等低频操作可以放键盘。额外鼠标侧键只作为重绑定便利，不能作为使用前提。

跳跃、移动和观察保留独立意图。不能默认把空格同时解释为跳跃和回避，否则同一个空间选择变得含糊。

## 3. 鼠标与锁敌的分工

| 状态 | 鼠标移动 | WASD | 攻击朝向 |
| --- | --- | --- | --- |
| 自由战斗 | 控制观察与期望瞄准 | 相对玩家逻辑观察朝向移动 | 按期望瞄准与动作转向限制计算 |
| 锁敌战斗 | 继续观察周围，第三人称可调整构图 | 建议相对敌我水平连线：接近、后退、环绕 | 朝向选定目标，但受动作转向、距离与遮挡限制 |

锁敌解决持续跟踪同一目标的问题，鼠标仍负责观察和选择注意力。锁敌不应让玩家同时持续用鼠标追踪目标才能攻击，也不表示攻击必然命中。

锁定输入建议点击切换；默认候选为鼠标中键，可重绑定。选敌按屏幕接近中心程度、距离和遮挡筛选，需要清楚目标标记。滚轮默认保留快捷栏，初版不默认占用为切目标。再次锁定输入先解锁，选新目标可重新瞄准再锁；是否增加快捷切敌需多人场景验证。

目标死亡、卸载或超出合法范围须按明确规则解除锁定，不能悄悄切到另一个目标后消费已经发出的攻击输入。遮挡持续多久解除与允许最大距离尚待决定。

锁敌绑定目标身份，不把每个攻击帧的轨迹自动旋转到目标身上。建议起手允许有界对准，进入承诺阶段后只保留招式明示的转向能力；冲刺和追踪动作仍受世界碰撞约束。

## 4. 双视角中的观察冲突

第三人称可以让镜头观察方向与身体攻击方向分开，采用有界的构图跟随，鼠标仍能看侧面。不能用镜头动画修改真实攻击方向。

第一人称若允许身体朝锁定目标、镜头完全看向另一边，会产生“画面外出刀”的理解问题；若强制镜头持续跟踪，又会与鼠标争夺控制。

用户认可弱跟随，并提出可通过配置在锁敌后自动切到第三人称。具体相机规则由[视角模块](../modules/presentation.md)维护：鼠标主动输入优先，自动跟随可关闭，自动切第三人称是可选的客户端偏好。

第一人称应有可见的攻击与目标提示。目标离开画面时的提示、跟随与锁定解除需要分别定义；不能因为玩家短暂转头观察便立即解锁。有效距离、遮挡和动作转向约束在两视角一致，不能把镜头视野差异直接变成攻击权限差异。观察角度与解除容差仍需验证。

F5 切换应保留动作实例、锁定目标和逻辑瞄准状态，不能因切换重启动作或重复伤害。镜头跟随可关闭，但规则边界保持一致。

## 5. 基础输入候选

| 输入候选 | 固定职责 | 说明 |
| --- | --- | --- |
| 左键 | 基础攻击 | 多种招式由明确动作图衔接 |
| 右键按住 | 防御 | 按下立即申请防御；精准格挡用真实按下时机 |
| Shift | 回避 | 建议在战斗状态下替代潜行；方向来自 WASD，无方向时行为需定义 |
| Q | 通用派生候选 | 通过动作图到达普通或 SA 分支；不表示仅装备一个技能 |
| 中键 | 锁定/解除 | 可重绑定，默认不要求鼠标侧键 |
| F | 模式激活 | 低频操作，固定模式入口；资源不足给清楚反馈 |
| WASD、空格、滚轮、E、F5 | 移动、跳跃、快捷栏、背包、视角 | 保留熟悉的基本职责 |

这是一套需要结合完整攻击流重新评估的布局，Shift 与 Q 的原版语义只有在明确战斗状态下才被接管；不能无提示改变。键位冲突仍需重绑定。右键退出与释放事件在 GUI/切武器时必须清理，避免残留格挡。

### 重攻击的取舍

候选 A：左键短按普通攻击、长按蓄力重击。省一个键，但为了区分意图，普通攻击通常要等松开或需要预备动作，存在输入延迟；不能宣称按下立即轻击且同一次按住又能无代价改成重击。

候选 B：左键立即普通攻击，增加一个重击输入（如 R 或可选侧键）。响应清楚，但增加高频键位。它应在重击具有独立破防/距离决策价值后再引入。

原“左右键、回避和一项 SA”的范围收缩遗漏了攻击流。修正为先建立包含普通继续、压制、反击、特殊转换与收束的最小动作图，再选择输入布局；不先强制给每个动作独立按键。若缺少进攻防守者的办法，应先设计这种战术选择，再比较 A/B；不能仅依靠高手 SA 或爆气解决基础攻防。

纳刀的候选方案是在脱离战斗后自动进入收势、攻击自动拔刀；战斗内居合的准备需要明确成本和入口。若主动纳刀确实提供独立玩法价值，再决定与哪个低频操作结合。自动收势不能突然截断玩家的合法衔接窗口。

## 6. Minecraft 交互需要可见的边界

仅按准星是否指向箱子或墙决定右键用途，会在近墙交锋中产生误操作。建议用清楚的探索/战斗状态统一管理接管：探索时保留挖掘、使用、潜行与丢物；战斗时左右键稳定表示攻击和防御。

进入候选：持有效武器按下锁定或战斗动作；退出候选：明确取消战斗，或安全状态切到非战斗物品。具体显式退出输入尚待决定，不能单纯靠锁敌键承担全部职责，因为自由战斗也必须存在。

探索时鼠标左键究竟攻击还是挖掘，仍需验证入口方案：可重绑定的战斗切换输入最清楚，但增加低频键；武器持有状态直接进入战斗最简单，但持刀开箱要先切物品；自动判敌则容易误判。本轮保留三者的取舍，不伪装为已解决。

打开 GUI 时取消输入接管并清理缓冲；换武器和 GUI 都不能绕过服务端动作恢复。战斗状态提示必须可见，回到探索后恢复原版输入。

## 7. 对框架的约束

核心接收 ATTACK、GUARD、EVADE、SPECIAL、MODE_ACTIVATE、LOCK_TARGET 等语义，不接收“F 键意味着重斩”之类硬编码。物理按键与武器动作映射分开，具体实现名字尚待统一。

角色观察、目标选择、实际攻击方向和镜头表现分别管理；目标与方向最终由服务端验证。模式激活保持已调整的 Burst 职责，不能因为重新设计键位重新引入三类自动爆气。

## 8. 原型验收

先覆盖自由近战、锁定 1v1、锁定时第三者靠近、目标绕身、贴墙、目标死亡、切快捷栏、开箱和 F5 中途切换。检查玩家能否边移动边执行紧急防御/回避，是否按出期望动作，锁定后鼠标是否争抢控制，以及两视角是否维持同一规则边界。

暂不固定缓冲 tick 数、镜头距离和跟随速度。原稿中方向加 F 的招式菜单、X 回避、R 纳刀、G 锁敌及 B 自动分类仅作为历史参考，不继续作为默认操作前提。
